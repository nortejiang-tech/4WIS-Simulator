# ADR：三种交互共享物理内核，Agent 使用隔离会话

状态：已实施；2026-09-09。基线为第一轮 ASTRA 物理修正后的未提交工作树。

用户要求同时支持人直接驾驶、工况脚本和 AI Agent 调用，且 Agent 是优先接口；输出需要图形、完整数据和图表。旧接口虽然已有实验/study 批跑，仍缺少可重试的短闭环 step/observe 语义，人工输入也会在无关页面持续发送。

## 决策

- 人工和实时动作脚本继续使用驾驶台上的 Simulator。键盘/手柄只能在驾驶页、页面聚焦、连接正常、手动输入已启用且脚本未运行时输出；失焦、导航离开、断开和超时释放输入。
- 默认 Agent 路径使用独立内存会话。每个会话拥有车辆、策略、场景、故障状态和积分时钟；不会抢占人工驾驶台。界面可观察所选 Agent 会话，并使用相同接口操作。
- REST/OpenAPI 是版本化执行契约；现有 stdio MCP 是薄适配器。保留已有研究工具并增加会话、工件和异步 study 工具。
- `request_id` 绑定完整请求内容；相同请求重试返回原回执，不同内容复用同一 ID 拒绝。`expected_revision` 拒绝基于过期观测的控制。请求以整数积分步推进，与墙钟无关。
- 所有执行宿主通过 `core/step.py` 使用同一驱动、制动、积分与派生力链。新增 `core/telemetry.py` 让实时全通道录制和 Agent 共享通道语义。已有批跑保留原有采样定义及黄金基线。
- 结果库 run 是共同持久输出。CSV/JSON 是完整已记录数据，ZIP 包含同一 CSV、元数据、校验清单和 SVG。图形预览抽样必须明确标记。

## 取舍

旧设计稿提出的实时控制租约会引入额外抢占、断连恢复和人机争用状态。本轮采用隔离会话，满足短闭环控制与人工并行操作，并减少物理状态被界面操作隐式改变的机会。此决策不声称已实现 Agent 驾驶人工窗口中同一辆车；该需求需要未来单独设计显式接管协议。

实时 YAML 动作沿仿真时间调度，但仍以约 50 Hz 异步轮询，适合可视化试用，不承诺逐积分步动作同步。严格重复的测试用 Agent 整步推进或声明式 Experiment/study。

实时录制使用有界内存缓冲。满缓冲丢弃旧样本时明确计数并标记不完整；时间倒退自动停止。未实现长时磁盘流式记录。Agent 限制每会话 20,000 步、单次 1,000 步、最多 4 个活动会话；关闭/重启前导出，长任务继续使用 study/batch。

## 验收与回滚

验收覆盖三模型分块一致性、人工实例隔离、重复和过期请求、数值失败保留、CSV/JSON/ZIP 精确回读、真实 stdio MCP 链路、浏览器响应丢失重试及输入释放。见 [阶段结果](../STAGE_interaction_2026-09-08.md)。

变更保留为当前分支未提交 diff，未发布便携包或修改宿主 MCP 配置。回退按第二轮基线逐文件审阅；不 reset/stash、不回退第一轮物理修正、不清理已有 run。
