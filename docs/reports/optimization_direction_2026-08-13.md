## 0. 摘要

测试门禁全绿（777 单元 + 279 v2 专项 + 32 smoke + 5 黄金 + 2 benchmark + 52 e2e）证明的是**自洽，不是正确**——塔基厚、塔尖空（L4 实测对照为 0）。

因此下一迭代的主线是：**修正确性、补安全网、起标定工作台**。

- **P0（本迭代，互锁三件）**：C1 轮胎本构层单源化 → S2 v2 黄金锚点 → C2 转向层多速率集成。
- **P1（下迭代）**：C3 标定/相关性工作台立项（长杆）；C4 / S1 / S3 / H1 并行低成本推进。
- **P2（储备）**：C5 / S4 / S5 / H2 / H3。

## 1. 三个再校准（决策前提）

### 1.1 全绿证明自洽，不证明正确

当前所有测试都在防范"改坏一个已经存在的东西"，抓不住"模型从一开始就不对"。D8（独立外部对照为 0）、D9（参数为工程估计值）才是决定工具结论可信度的两条，其余是内务。全绿不是扩张信号，是安全改造的许可证。

### 1.2 D3 与 D5 同根：多时间尺度 + 单一采样率

被控对象层的模态跨 3 个数量级：整车 ~1 Hz、转向柱 ~10 Hz、助力回路 5× 以上（`test_assist_raises_the_mode_the_step_has_to_carry`）、电机电学更快。D5 的机理不是积分器精度，是**外环零阶保持**：指令在 5 ms 外步内不变，共振峰落在两个采样点之间就被错过（峰值 51% 且未收敛，RMS 只动 7%）。全局缩步长、指数积分都只是打地鼠；正确方案是多速率集成（§2.3）。D3（边际带振荡）大概率同源收敛。

### 1.3 D1 是类缺陷的第二例：平行实现

钉住测试 docstring 原话："same defect class … this is a second instance"。两条平行代码路径各自实现本构律（侧偏刚度），必然各自漂移。修一处是打地鼠，收敛为单一实现才是修复。参见 §6 贯穿性判断第一条。

## 2. P0 —— 本迭代（互锁三件）

### 2.1 C1：轮胎本构层单源化

| 项 | 内容 |
|---|---|
| 目标 | 准静态路径与时域模型解的是**同一台车**；同类缺陷不再有第三例 |
| 现状 | `dynamic.py` 按轴缩放侧偏刚度（默认 0.80 前 / 1.20 后）；`quasi_static_wheel_loads` → `load_sensitive_cornering_stiffness` 没有这一步。后果：稳态横摆 −5% @30 km/h、−17% @60 km/h（幅值无关、随 v² 增长，因它移动的是不足转向梯度 K） |
| 做法 | 1) 全库 grep 所有侧偏刚度计算点（含 `axle_cornering_stiffness()` 里 decoupling study 记录过的第一例）；2) 收敛为一个带轴分配参数的单一函数；3) 准静态路径改为调用它，不保留平行实现 |
| 验收标准 | ① `errors[30]` 不再 < −0.02、`errors[60]` 不再 < −0.10；② **删除** `test_analytic_path_omits_the_axle_cornering_split` 与 `with_axle_split` 开关（测试存在即缺陷存在）；③ 黄金实验 5/5 不受影响（转向层关闭路径）；④ 负载分析页与自行车增益 demo 数值变化在 CHANGELOG 中作为**修复**记录，不当作回归 |
| 风险与处置 | 负载页/原理页显示值将变化 5–17%——这是修复本身的证据；历史研究报告（`steering_decoupling_value.html` 等）**不重跑**，标注"基于修复前模型生成"即可 |

### 2.2 S2：v2 黄金锚点

| 项 | 内容 |
|---|---|
| 目标 | oncentre weave 的 10 个过程指标有回归保护；C2 改造核心数值路径前必须有它 |
| 现状 | 黄金实验 5 项全部在转向层**关闭**下跑；v2 的 `procedures/iso13674_oncentre.yaml` 指标（力矩梯度 ×2、0.1 g 手力矩、迟滞环宽、死区、角度梯度、横摆相位滞后、实际幅值/方向盘幅值/频率）没有任何回归保护 |
| 做法 | 1) 以 procedure 的 baseline（100 km/h、0.2 Hz、前轮 0.4°、转向层开启、50 Hz 记录）跑一次并锁定 10 个指标值；2) `check_golden_experiments.py` 支持 steering overrides 与**过程指标**（或经 study runner 路径落盘后由 oncentre 分析器计算——实现二选一，接口不变） |
| 验收标准 | 改动 `plant.py` / `oncentre.py` 任一参数或算法，黄金检查失败；耗时增量 < 30 s |
| 风险与处置 | 黄金 checker 目前只认 KPI——过程指标接入是其首个真实使用点，若因此需扩展 checker 接口，属于 P0 范围内的必要改动 |

### 2.3 C2：转向层多速率集成

| 项 | 内容 |
|---|---|
| 目标 | 峰值手力矩不再欠解析（按构造消灭 D5）；边际带振荡收敛或变为可判定（D3） |
| 现状 | 单一 5 ms 外步 + 指令零阶保持：峰值 1.864 → 2.812 N·m（5 ms → 0.5 ms，51% 且未收敛）；助力后模态 >5× 固有频率（~50 Hz+） |
| 做法 | 1) 转向层以 0.5 ms 内步率运行（10×），指令**插值**而非保持（与 `view/renderPose.ts` 航位推算同理：给内环更细的连续激励）；2) 车辆外环保持 5 ms 不动；3) 转向层输出（δ、hand_torque）在 5 ms 边界对齐回外环。成本上可行：转向层 ODE 只有几个标量，多跑 10 倍几乎免费，不拖整车 |
| 验收标准 | ① D5 钉住测试反转：0.5 ms 内步峰值与 0.25 ms 参考差 < 2%，删除"欠解析"钉住断言；② `test_disabled_plant_changes_nothing`（位级 `==`）仍通过；③ 黄金 5/5 + S2 新锚点全过；④ 边际带场景重跑：振荡若仍在，守卫行为（拒绝给余量）不变并记入 CHANGELOG；若收敛，更新该条已知项 |
| 风险与处置 | **选型峰值与 `eps_actuator` 判定数值会变**（旧值是欠解析的）——需重跑 `sim4wis targets check eps_actuator` 与 `test_targets` 中的期望值，新值大概率"更真实"，但要评审方向是否合理；记录通道仍按 record_hz 采样，50 Hz 记录对 0.2 Hz weave 足够，此点写入文档 |

### 2.4 P0 落地顺序与提交建议

顺序：**C1 与 S2 可并行；C2 必须在 S2 之后**（先建锚点再动核心数值路径）。

建议提交（与仓库增量风格一致，每个增量带测试 + CHANGELOG 条目）：

```

```

Inc3 落地后重新跑一遍 `docs/reports/test_report_2026-08-13.md` 的 §0 全量表，作为本迭代收尾验证。

## 3. P1 —— 下一迭代

### 3.1 C3：标定/相关性工作台（长杆，最高杠杆）

incoming 工具链（scaffold/normalize/suggest/promote）只解决了"数据进来怎么登记"，没解决"数据进来怎么用"。缺一个**参数辨识模块**：给定实测 weave/阶跃，拟合扭杆刚度、齿条摩擦、助力表、轴侧偏分配 + 逐通道残差面板（model vs measured）。它把 D9 从免责声明变成标定工作流，把 L3→L4 变成工程动作，让 targets 的绝对判定第一次有依据。

分阶段：

| 阶段 | 内容 | 验收 |
|---|---|---|
| 3.1a | 数据管道 + 残差面板：外部数据经 normalize 后与同工况仿真通道对齐，逐通道误差表/图 | 给定一份 weave 台架 CSV，一键产出残差报告 |
| 3.1b | 参数辨识：4–6 个转向参数的最小二乘/贝叶斯拟合 | 拟合后残差显著低于默认估计值参数；拟合过程可复现 |
| 3.1c | 集成进 targets check：判定随附"参数空间余量"（配合 C5） | 达标项注明"参数要错多少才会翻" |

护栏：**第一版只输出"标定 + 残差"，不自动改写参数库**——避免把拟合当真相。首个标的建议 ISO 13674 weave 台架数据。

### 3.2 C4：摩擦的频域分离协议

D2 的根因：0.2 Hz 下车辆侧向动力学滞后与摩擦项的正交分量同量级（0.99 / 0.26 / 1.66 N·m 非单调）。ISO 套路本身就是频域分离——补一条**极低频慢斜坡**工况（0.02–0.05 Hz 或准静态往返），动力学分量消失后摩擦单调可测，迟滞环宽才配得上写摩擦要求。顺带为 D4（松手）铺路：慢工况里加 release 事件类型最简单。验收：慢斜坡下迟滞环宽对齿条摩擦单调，`steering_feel` 摩擦条目从参考项升为判定项。

### 3.3 S1：统一实验体系

黄金实验（5 场景 + 容差）与客观试验库（procedures/，1 个）是两个平行体系。把黄金实验移植成 procedures 模板（工况钉死 + criteria + 报告），黄金回归成为 procedures 的定点子集。顺带收益：黄金回归自动获得过程指标与出处字段。

### 3.4 S3：MCP 服务器

平台论文设计了 agent 接口（study 层 + MCP，与 `/api/study/*` 同契约），服务未发货。发货后"设计 → 跑 → 判 → 报告"闭环可被 agent 编排。门槛低（契约已定），价值是平台性质的。验收：agent 仅凭 MCP 工具完成一次"新建 spec → dry-run → run → 读报告"。

### 3.5 H1：渲染平滑性机器验证

3D 车顶视角的 6.7 Hz 拍频修复目前只有人眼验证。Playwright 注入 rAF 时间戳，断言帧间隔无周期性顿挫，变成回归测试。验收：帧间隔序列无 66.7 ms / 100 ms 周期拍频成分。

## 5. 护栏：明确不做

1. **C3 落地前，不新增任何"绝对验收"类目标集条目**——否则就是把工程估计值当成要求固化，与工具自己的适用边界声明矛盾。
2. **参数辨识第一版不自动改写参数库**（见 §3.1 护栏）。
3. **历史研究报告不重跑**：C1 修复后旧报告数值作废但不翻新，标注模型版本即可——重跑会毁掉"当时模型当时结论"的可追溯性。
4. **转向层"关闭位级不变"契约不可破坏**：任何核心回路改动以 `test_disabled_plant_changes_nothing`（`==` 断言）为红线；违反它等于改写了 v1 全部已发布结论。

## 6. 贯穿性判断（三原则）

1. **平行实现是仓库的第一失败模式**：解析 vs 时域（D1）、golden vs procedures、KPI vs 过程指标——CHANGELOG 里漂亮的缺陷修复，一大半在给平行实现漂移买单。每次新增能力先问"这是否是已有本构律/体系的第二个实现"，是则先收敛。
2. **测试资产价值排序**：偏差钉住测试 > 不变量测试 > 拒绝规则测试 > 行为回归 > 覆盖计数。写新测试优先把"已知缺陷"和"错误工况拒绝"钉住，而不是堆行数。
3. **自洽是必要条件不是充分条件**：所有优化服务于同一战略——把"工程估计值"变成"经标定、带残差、可外推的参数"。C3 是主战场，其余（含 UI）为其清扫道路。
