## 路由决定

本阶段包含发布门禁、便携包装配、跨平台启动验证、GitHub workflow、标签、发布资产与远端回读。根据本项目的
软件开发状态机，这些是发布/交付边界工作，不能把本地 Coder 的结构化 `PASS` 当作发布验收；因此由 ASTRA
直接完成并保留完整的独立验证证据。没有调用 Spark 或 Luna fallback，也没有为了生成统计而进行无必要的
EVO-Coder 试调用。

在收尾过程中发现并修复了一个真实状态语义问题：停止录制应保留数据用于导出或保存，浏览器用例却假设停止会清空
缓存。现在新增受控的「丢弃录制」接口和界面动作；它仅可用于已停止的录制，不重置仿真，也不删除已保存的 run。

首次 Windows 原生烟测还准确捕获了一个便携包缺陷：MCP SDK 将 `pywin32` 放在 Windows 平台标记后，macOS
交叉装配时没有把它带入 vendor，导致 stdio MCP 在 `pywintypes` 导入处失败。ASTRA 直接修复了目标依赖、
Windows 启动器的导入路径、`--update` 的缺失依赖刷新，以及损坏下载缓存的原子替换；验包器现在同时检查 wheel
内容和启动器路径。这个发布/跨平台门禁修复不进入 EVO-Coder 路由，后续 GitHub Windows runner 仍是最终原生证据。
