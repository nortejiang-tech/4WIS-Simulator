## 1. 概述

### 1.1 要解决的问题

策略层输出的 `delta_cmd` 在指令层早已四轮独立，但执行层只有两个通道（前轴一个 plant、左右轮被平均；后轴一个一阶滞后模型），且线控前轴的"角度跟随"是开环指数趋近——没有位置闭环、没有积分、负载不进角度方程。本层在指令与执行器之间插入**可替换、可调参、逐轮独立**的角度跟随控制，终极目标是评估与开发 4WIS 转角跟随控制策略。

### 1.2 交付范围

| 交付 | 内容 |
|---|---|
| 骨架 | 控制器协议、力矩型角执行器、角度传感器（量化/延迟/种子噪声）、按架构生成逐轮通道（SBW 前轮 / RWS 后轮 / 4WIS 四角） |
| 控制库 | open_loop（基准）、pid_single、pid_cascade、lqr、dob、adrc、smc、mpc、h_inf |
| 前馈积木 | 齿条力/动力学、速度+加速度、摩擦补偿——独立开关、任意叠加 |
| 调参 | 解析（极点配置）、继电辨识（Åström–Hägglund 带滞环）、黑盒精修（Nelder-Mead），110% 验收门 |
| 评估 | 阶跃过程指标族 `trk_*` + procedure 模板 + 真实工况验证脚本（5 工况 × 9 控制器） |
| 外部接口 | Simulink/FMU 端口契约 + 三原语 + 参考适配器 `file_gain`（加载器留给生产环境） |

## 2. 设计

### 2.1 层定位与数据流

```
ControllerStrategy.compute → delta_cmd[4]（rad，逐轮）
        │
        ├─ 关闭层（默认）：legacy 路径（前轴 plant / steer_actuator），逐位不变
        │
        └─ 开启层：CornerTracker × N（按架构）
                每个 corner：Controller（2 kHz 内环，目标角 5 ms 内线性插值）
                             + CornerActuatorPlant（力矩型二阶对象）
                             + AngleSensor（量化 + 管线延迟 + 可选种子噪声）
                负载：rack_force[i] × pinion_radius（外环量，步内保持）
        → delta_act[4] → 轮胎
```

**两条基石契约**（均被测试钉住）：

1. **关闭层位级不变**——`angle_control.enabled` 默认 False，全部旧路径原样运行；全套 872 测试与黄金 6/6 在层存在的情况下通过即是证明。
2. **open_loop 与旧线控更新逐位一致**——启用层 + 默认控制器不改变任何已发布数字；这使 open_loop 成为一切控制器评估的天然基准。

### 2.2 组件设计

**控制器协议**（`controller.py`）：一步 `step(dt, target_angle/rate, feedback_angle, plant_angle, load_torque, speed_ms)`，输出二选一——直接给角（open_loop 专用，绕过执行器对象）或力矩指令（驱动执行器）；控制器自声明更新率（`inner_rate_hz`，None = 每外环帧一次的 legacy 语义）。

**角执行器**（`plant.py`）：轮域二阶 `J·θ̈ + b·θ̇ + F_c·sign(θ̇) + τ_load = τ_sat`，库仑摩擦带静摩擦保持（中心死区是物理结果而非控制伪影）；峰值力矩 120 N·m（按仓库选型模块定尺寸，见 §4 缺陷 1）。

**传感器**（`feedback.py`）：量化（默认 0.00017 rad ≈ 0.01°，解码器/旋变步长）+ 管线延迟（1 个控制周期）+ 种子噪声（默认关，可复现）。反馈控制器看传感器，open_loop 看对象真值——它复现的行为先于传感器存在。

**多速率耦合**（`coupling.py`）：反馈控制器 2000 Hz 内环 + 目标角插值（D5 教训的直接应用：指令台阶欠解析）；负载/车速外环量步内保持；输出在 5 ms 边界对齐。每角独立控制器实例（积分器/滤波器是逐角状态，共享实例会静默耦合四角）。

**前馈积木**（`feedforward.py`）：

| 积木 | 公式 | 备注 |
|---|---|---|
| 齿条力/动力学 | `τ = gain·τ_load`（可选低通） | 齿条力本身已滞后一步——**默认不放低通**（教训见 §4） |
| 速度+加速度 | `τ = b·ω_ref + J·α_ref` | 补偿参考动态而非扰动 |
| 摩擦补偿 | `τ = F_c·tanh(ω_ref/ε)` | 平滑过零，无抖振 |

**与 DOB 的互斥**：扰动观测器本身就是负载/摩擦补偿器——观测器无法从指令力矩中区分"抵消负载的力矩"与"负载本身"，叠加前馈即双重补偿（实测后果见 §4 缺陷 3）。构造期拒绝，报错讲明原因。

### 2.3 控制库（9 种）

| 控制器 | 结构 | 设计要点 |
|---|---|---|
| open_loop | 一阶带宽限幅+速率限幅，直接给角 | legacy 逐位复现；评估基准 |
| pid_single | `τ = kp·e + ki·∫e − kd·ω_meas + τ_ff` | D 作用于测量速率（抗微分冲击）；积分钳位；车速增益调度（线性插值） |
| pid_cascade | 位置 PI → 速度 PI | 量产 EPS/SBW 形态；积分双钳位 |
| lqr | [∫e, e, ω] 增广状态反馈 | 离散 Riccati **Newton 法**——跟踪对象含纯积分器（特征值在单位圆上），朴素定点迭代收敛到反稳定解；从极点配置稳定初值解起（"PID 设计精修到最优"） |
| dob | PD 基底（无积分）+ 扰动观测器 | 观测器即负载补偿器；估计钳位 60 N·m；与 rack/friction 前馈互斥 |
| adrc | 线性 ESO（三阶，Gao 带宽参数化）+ PD 律 | 只需 b0=1/J，模型依赖最低 |
| smc | s = ė+λe，tanh 边界层 | 切换增益必须 > 扰动界（§4 缺陷 2）；稳态停留在边界层内是解析均衡而非缺陷 |
| mpc | 积分增广 + 凝聚 QP + Hildreth 主动集 | 唯一显式规划 \|u\|≤u_max 的成员；QP 矩阵全部预计算（§4 缺陷 4） |
| h_inf | game Riccati 状态反馈（Hamiltonian 稳定子空间） | 唯一有扰动衰减**界**（L2 增益 < γ）的成员；γ 不可行构造期拒绝 |

### 2.4 调参工作台

三通道串联：**解析**（模型给定→增益给定）→ **继电辨识**（带滞环继电试验 → Ku/Tu → ZN 表；滞环不可省，否则测到的是采样率）→ **黑盒精修**（Nelder-Mead on ITAE 归一阶跃成本 + 峰值力矩惩罚，确定性、评估记忆化）。**110% 验收门**：精修成本 ≤ 1.1×解析基线才被接受，否则如实报告解析增益——不"加冕"失败的搜索。发布默认增益由 `scripts/tune_vehicle_defaults.py` 在**车辆闭环**（齿条力滞后一步 + 轮胎回正弹簧在环）调出，脚本即出处。

### 2.5 外部接口（Simulink）

端口契约（轮域六入一出）、三原语（init_backend / _invoke / shutdown）、参数出处强制（无出处即拒绝运行）。参考适配器 `file_gain`（JSON 增益表）跑通完整契约；真实 FMU/代码生成加载器为生产环境工作，接口已冻结。

### 3.2 解析钉住（每个控制器的数学契约）

| 对象 | 钉住内容 | 实测 |
|---|---|---|
| 极点配置 PID | 特征多项式 `J·s³+(b+kd)s²+kp·s+ki ≡ (s+p)(s²+2ζωₙs+ωₙ²)` | rtol **1e-12** 内一致 |
| LQR 增益 | Riccati 残差 `\|Q+A'PA−A'PB(R+B'PB)⁻¹B'PA−P\|` 与出厂增益对独立求解的一致性 | 残差 < 1e-6·max(Q)；增益一致 rtol 1e-9 |
| 执行器对象 | 纯惯性阶跃的半隐式解 `θ = τ/J·dt²·k(k+1)/2` | rel **1e-12**；静摩擦带内保持（10 步零位移）；峰值饱和精确 |
| 传感器 | 种子确定性（两次构造序列相等）、量化格点、管线延迟阶数 | ✅ 全过 |
| MPC | 无约束首步向无限时域 LQR 律收敛；**硬盒精确尊重** | H=4 差 0.87% → H=20 差 0.70%（单调收敛）；\|u\|≤5 N·m 时实测 5.0+0 |
| H∞ | game Riccati 残差 + 闭环 Hamiltonian 稳定 + γ 不可行拒绝 | 残差 ~1e-6；特征值全左半平面；γ=0.05 构造期 ValueError |
| ADRC | ESO 增益 = 带宽参数化 `[3ωo, 3ωo², ωo³]` | 精确相等 |
| SMC | 稳态滑模面停留在边界层内（s = φ·atanh(d/k) 是解析均衡） | 全部 \|s\| < φ |
| QP | 解析盒约束解（min (u−2)² s.t. u≤1 → u*=1） | 1e-9 内 |
| 阶跃指标 | 一阶系统 rise=τ·ln9、settle=τ·ln50、静态 toe 不计入误差 | rel 5%/8% 内；toe 残差 < 1e-10 |

## 4. 真实工况暴露的缺陷与修复（本轮验证的核心产出）

每项都有修复前后的实测数字；这些教训已固化为设计约束与文档。

| # | 缺陷 | 现象（实测） | 根因 | 修复 | 修复后 |
|---|---|---|---|---|---|
| 1 | **角执行器峰值 40 N·m 尺寸不足** | 3° 阶跃 @60 km/h，轮被负载吹离指令漂到 **−0.34 rad**；PID 与前馈被同一饱和封死 | 0.5 g 每角回正负载 ≈40 N·m 恰好压在极限上，零裕度 | 按仓库选型模块定尺寸（全锁驻车 ≈104 N·m/角）→ 默认 **120 N·m** | 全控制器 step_60 偏差 ≤0.006 |
| 2 | **SMC 滑动可达性被违反** | weave@100 直行段轮被吹到转向限位（偏差 0.618 rad） | 切换增益 k=12 ≤ 直行回正负载 ≈12 N·m，tanh 饱和后无回位力矩（滑动条件 \|d\|<k 不成立） | k → **25 N·m**（覆盖 ≤1.25 kN 齿条力） | weave/ramp 偏差 0.0018（全库最优档） |
| 3 | **DOB 双重补偿**（结构语义缺陷） | 叠加齿条力前馈后轮漂离指令 **0.26–0.60 rad**（四工况） | 观测器无法从指令力矩中区分"抵消负载的力矩"与"负载本身"→ 同一扰动补两次 | **互斥语义**：构造期拒绝 rack/friction 前馈块；基底去积分（DC 动作归观测器）；估计钳位 60 N·m | 全工况 0.005–0.007 rad |
| 4a | **MPC 内环性能** | 每步重建凝聚 QP 矩阵（2000 Hz 内环做矩阵幂） | 状态无关矩阵未预计算 | 预计算至 `__init__` | 单角 **28× 实时**（2 s 仿真 0.07 s 墙钟） |
| 4b | **LQR 构造性能** | 每角构造 **5.6 s**（Lyapunov 朴素定点迭代） | 逐项迭代收敛慢 | 倍平方算法 | **1.1 ms**，增益逐位不变 |
| 附 | 超包线发现（保留为发现，非缺陷） | 5°@60 km/h（≈0.8 g）深滑移区回正力矩反转，可把 120 N·m 执行器钉在限位 | 超出轮胎包线是**选型维度**问题 | 由偏差通道如实标记；对比工况保持在包线内（3°） | —— |

另修复：adrc/h_inf 缺失的前馈接口补齐；阶跃指标对静态 toe 的基线校正；非阶跃工况（weave）调用阶跃分析时明确拒绝。

## 5. 结论

1. **层已具备产品级骨架与完整控制库**：9 种控制器、3 类前馈积木、三通道调参、评估协议与外部接口契约全部落地，63 项专项测试 + 全仓 872 项回归 + 黄金基线全部通过，两条位级不变契约成立。
2. **真实工况验证闭环建立并全绿**：5 类真实工况 × 9 控制器 45/45 通过，且该轮验证抓到了 4 类在对象级测试中不可见的缺陷（执行器尺寸、滑动可达性、双重补偿、两处性能）——验证矩阵的价值已被证明，任何后续控制器改动跑一条命令即可复验。
3. **控制器特征与文献同向、差异可解释**：级联 PID 超调最小、LQR 最快最干净、SMC 在连续工况与开环同档、DOB 的负载恢复以初始瞬态为代价、MPC 提供唯一显式约束处理、H∞ 提供唯一扰动衰减界——评估维度（快速性/稳态精度/抗扰/约束/鲁棒）已被不同成员覆盖。
4. **诚实边界**：dob/adrc/mpc/h_inf 的默认增益是对象级整定值（车辆级阶跃 settle 偏慢，如实呈现在 §3.3）；parking 工况不承载准静态驻车负载（模型边界）；0.8 g 超包线行为是选型问题而非控制问题。

## 6. 后续迭代方向

1. **进阶控制器车辆闭环调参**：把 `tune_vehicle_defaults.py` 的流程扩展到 dob/adrc/mpc/h_inf（含其结构参数：ωo/ωc、γ、horizon），预期将其车辆级 settle 拉到 v1 档；调参结果连同参数空间余量（复用 C5 margins）入库。
2. **评估协议补全**：正弦扫频（带宽/幅值衰减/相位滞后）与负载扰动注入（阶跃/正弦回正力矩下的误差恢复——DOB/ADRC 的主场）两个工况族模板；与既有 procedures 体系对齐，等工况模块大改时按工况族重构。
3. **执行器链路细化**：逐轮齿条力折算目前是一阶近似（rack×pinion_radius）；引入角执行器规格模型（传动链柔度/间隙），与选型模块闭环互证。
4. **调参工作台工程化**：tune() 接 CLI、工况集加权指标（多工况 Pareto 而非单点成本）、与 study 扫掠打通（网格/贝叶斯）。
5. **Simulink 通道落地**：生产环境接入 FMI 2.0 共仿真加载器（接口已冻结，仅实现 `_invoke`/`init_backend`），用真实 Simulink 模型跑通一次闭环评估。
6. **超包线行为研究**：深滑移回正反转对执行器选型的定量要求（多大峰值才不会被吹到限位）——这是给选型模块的一条新输入。

## 7. 方向 3 落地增补（2026-08-15 第四轮：柔度调参/鲁棒化）

双质量传动（k=1200 N·m/rad → **17.8 Hz 共振**，J_m:J_w = 0.12:0.48）开启后，
发布默认增益全部失稳（1° 阶跃超调 952/1322/1158%，pid_single/cascade/lqr）。
机理：**轮侧速率反馈从电机力矩侧激发双质量共振模态**（闭环极点分析：共振模态
实部 +2～+33）——非共置反馈的经典失稳；D 项去掉即稳（PI 69.9%），速率通道低通
（τ=0.05）到 9.2%，电机侧速率阻尼（共置教科书解）7.8%，输出陷波 12.9% 但组合脆。

落地内容与实测数字：

| 通道 | 内容 |
|---|---|
| 工作台柔度通道 | `step_cost`/`relay_identify`/`tune()` 接受传动参数；共振安全解析种子（wn=ω_res/8、τ=5/ω_res）；`deriv_tau_s` 入轴；110% 验收门不变 |
| 角级 before/after（超调） | pid_single 952→32% · pid_cascade 1322→17% · lqr 1158→15% |
| 车辆级发现 | 角级增益不迁移（车辆横摆动态与压低后带宽同频）；15 Hz 齿条力前馈低通是柔度环失稳元凶（642%→53%） |
| 车辆级最终（柔度 procedure） | pid_single os 0.1%/settle 0.42 s · pid_cascade 外环纯 P os 0.0%/settle 0.36 s · lqr os 0.1%/settle 0.29 s；后轮串扰 ≤0.008 rad；3/3 判据绿 |

发布默认增益不变（红线）；柔度配置是评估维度（`procedures/tracking_compliance_step.yaml`），
其增益出处为 `scripts/devtools/compliance_tuning.py`（确定性多起点：角级种子 + 共振安全
解析种子 + warm-start——车辆成本面多峰，实测两种子局部最优 0.43 vs 1.50）。

**间隙量化（车辆级，柔度调参 pid_single）**：≤5 mrad 间隙可接受（超调 0.1→3.0%，
中心区极限环 0.0007 rad）；10 mrad 退化（35% 超调、狩猎 0.012 rad）；20 mrad 越限
（192%、峰值偏差 0.051 rad）。精密齿轮箱在可接受档；更大间隙需抗间隙结构。
剩余项：电机侧传感器通道（柔度环带宽的根本解）、抗间隙结构、柔度扫频/扰动臂。
