# 两条 C++ 路线的物理与数值验收边界

本次以稳定 v0.105.0 的物理修订为基线。A 将数值热点迁入 C++；B 复用完全相同的 `backend/native/core.hpp`，再迁移宿主与服务。二者的外层 5 ms、动力学内部最大 1.25 ms、事件切步、转向输入斜坡和原有物理回归标准不因提速而放宽。

|复核项|实际验收方法|结论范围|
|---|---|---|
|质心与车体受力|随机非中心质心、指定外力和力矩，独立 Newton–Euler 平衡断言|验证程序中的力、力矩、惯量与坐标变换一致|
|轮荷|支承力总和、未饱和俯仰/侧倾力矩与非负载荷|饱和支承只表示模型限幅，不预测翻滚|
|轮胎与轮速|线性/Pacejka 摩擦圆与隐式轮速角冲量；反向行驶和制动过零|验证合力约束与角动量更新，不能代替轮胎实测标定|
|机构力链|主销/连杆/齿条的虚功、机构几何奇异与行程限制|保留原几何和估算参数适用范围|
|卡滞与自由转向|锁住机构坐标，避免前束重复叠加；继承角速度，验证静摩擦区、耗散和止挡|共享齿条配置拒绝不适用的独立轮端机械故障|
|多点同时/错时/恢复|8 类故障 × 4 轮 × 2 动力学；非网格边界、冲突原子拒绝；实时/批跑/Agent 对照|真实事件时间线与观测输出可复现；不是多故障容错策略认证|
|传感器故障|偏差/噪声/掉线叠加、随机种子、只读查询不消耗随机数|本版本故障只改变观测，不自动进入控制反馈|
|迁移一致性|逐通道数值对照、精确时间与事件、6 个冻结黄金工况、2 组解析基准/15 指标|证明软件迁移一致性；黄金值本身不是物理正确性的独立证明|

具体检查见 `backend/tests/test_native_core.py`、`test_physics_audit_v105.py`、`test_multipoint_faults.py` 和 `test_longitudinal_invariants.py`。B 的 `cpp_backend/tests` 对原生可执行文件进一步比较模型、轮端控制、随机数、路径、研究分析、指标与实际 HTTP/MCP 行为。各平台实际测试数量和通过状态以对应 `acceptance.md` 为准。

本次复核还修复了选型载荷曲线混入其他车轮受力，以及 Python 版本求和差异造成选型时长上限少一步的问题。两条路线使用相同修复；严格选型/目标判定对照没有放宽。详情见 `sizing-correction.md`。

整体耦合仍为分区方法，不能因车体内部使用 RK4 就宣称整体四阶。独立轮端故障模型忽略转向惯量对车体的反作用、完整三维主销投影与高频摆振。选型继续采用单侧负载对称镜像，未新增非对称双侧精确齿条求解。更小相位差研究仍需要降低外层步长并重复收敛分析。

台架、实车、真实轮胎/机构参数、用户物理输入设备和外部 FMU/MATLAB 模型验收为 PENDING；本轮未操作车辆或物理 CAN。软件测试通过不构成这些项目的验收。回滚为停止当前候选、启动独立稳定目录；没有用户数据格式迁移。
