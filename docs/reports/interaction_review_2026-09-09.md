# 4WIS 交互接口与界面第二轮评审

2026-09-09。结论：**本轮软件内部验收 PASS**；真实手柄/方向盘与实车/台架相关性 **PENDING**。分支仍为 `codex/astra-dynamics-review`，未提交、未发布便携包。

## 交付结果

顶部导航明确提供手动驾驶、脚本工况和 AI Agent。人工/实时脚本共用驾驶台，Agent 默认使用独立固定步长会话。三个入口通过持久 run 连接完整 CSV/JSON、ZIP、SVG 和原有分析页。

新会话契约为 `4wis.agent.v1`，支持能力发现、创建、观察、整步控制、幂等重试、版本冲突拒绝、失败保留、持久导出与关闭。现有 MCP 的 8 个工具保留，新增 9 个，共 17 个；同时增加非阻塞 study 提交/轮询。

操作与完整请求示例见 [使用说明](../interaction_guide.md)，设计取舍见 [ADR](../adr/ADR-2026-09-09-interaction-sessions.md)。早期 Agent 设计稿已标明与当前实施的区别。

## 发现及处理

| 问题 | 修正和实际意义 |
|---|---|
| 驾驶键盘监听持续作用于无关页面；逐轮/全向目标可能持续锁存 | 页面/焦点/编辑/连接/脚本状态统一门控。显式释放当前连接的输入，清理动态 mode 参数和前端巡航/保持目标；非拥有者不能释放别的连接。断连不重放旧驾驶包，后端另有超时释放。 |
| 实时脚本依赖墙钟，暂停时仍可能进入后续动作 | 调度和渐变以仿真时钟推进；异常保留并显示，结束释放输入。零时长循环主动让出执行，避免饿死积分与停止请求；非有限/负时间参数在执行前拒绝。 |
| Agent 无法可靠表达“观察一次、保持控制推进 N 步” | 独立会话、整数步数、修订号和请求 ID。三种模型下，等价控制的分块推进与一次推进数组一致；独立于人工状态。 |
| 请求超时可能导致重复积分或错误成功 | 完整请求哈希去重，冲突返回 409。浏览器实际验证：后端完成后丢弃响应，再重试仍只有 200 个样本。数值失败保留已接受前缀并标记 failed，不静默 reset。 |
| 三种输出入口分散；实时录制未覆盖轮胎/执行器通道 | 统一结果面板，实时和 Agent 共用 158 通道定义及单位，包含轮胎力、滑移、轮位、力链、执行器和有效性标志。未知/未建立模型信号明确缺失。 |
| CSV 使用 6 位有效数字，图形数据与完整记录容易混淆 | CSV 使用 17 位有效数字保持 float64 往返，JSON 读取同一持久 CSV，ZIP 保留原 CSV 字节和哈希清单；预览与 SVG 明确标注抽样。 |
| 缓冲溢出/重置后可能将剩余数据当作完整工况 | 记录丢弃数量及停止原因；时间倒退自动停止，complete=false。保存要求先停止，重复保存返回同一个 run。 |
| 窄屏 grid 轨道超宽，body.scrollWidth 却未暴露裁切 | 修正最小内容宽度和导航换行，实际检查元素边界与截图；脚本视图填满剩余高度。Agent 页不再显示人工实例车速作为当前会话状态。 |

第一轮物理模型文件保留，本轮不重调模型参数。实时、脚本、Agent 的共用积分调用只提取既有驱动/制动/积分/派生力链顺序，未另建一套物理模型。

## 尚未验证的边界

- 真实手柄/方向盘的浏览器识别、轴/踏板校准及连续驾驶；本轮没有实现或验证力反馈输出。
- 无限期录制与磁盘流式落盘。实时内存缓冲默认约 30 min，溢出明确标记；Agent 每会话 20,000 步上限，长任务用批跑/study。
- 实时动作脚本为约 50 Hz 轮询，不承诺逐积分步同步；严格可重复工况使用整步会话或声明式实验。
- Agent 与人工共享同一实时车辆的显式接管/租约协议；本轮选择独立会话。
- 实车/台架相关性、真实车辆安全性能结论、已发布便携包和实际宿主 MCP 配置。当前内部测试通过不能替代这些验收。
