# 转向系统被控对象层 — 使用指南

> 面向：转向控制、系统、选型、功能安全工程师　·　v2 V1+V2　·　2026-08-12

本文讲**怎么用**。设计取舍与分期在 [`v2_steering_platform_plan.md`](v2_steering_platform_plan.md)。

---

## 0. 先说清楚这些数字值多少

**本层经解析闭式解与内部一致性验证，golden 基线逐位可复现；尚未与实车或台架数据做
相关性验证。** 转向系统参数（扭杆刚度、齿条摩擦、电机常数……）是**工程估计值**，
不是实测硬件。

这不是免责声明，是使用前提：**用它做趋势判断、架构对比、敏感度分析是成立的；
用它给出绝对值去定验收指标，不成立**，除非你先用台架/实车数据把参数标定过。

数据到位后接进 `validation_data/`，门禁会自己转绿——接口留着，不需要返工。

## 1. 它补上了什么

在此之前，仿真器的转向链是：

```
归一化输入 →〔手感层 i(v) + μ 软限位〕→ δ_cmd →〔一阶滞后 + 速率限〕→ δ
                                                                    ↓
                                        轮胎力 → 主销力矩 → 齿条力（诊断输出）
```

主销那一段（Reimpell 口径，机械/气胎拖距分离）质量很高，但它是**链条的终点**。
从方向盘到齿条的整个系统不存在，因此：**没有扭矩传感器信号 → 没有任何 EPS 控制律的
输入 → 没有手力矩输出**。

现在补上了：

```
θ_sw ──柱 J,c,摩擦── 扭杆 K ──┬── 小齿轮 ── 齿条 ──（既有力链）
                              │
                    扭矩传感器 τ_tb ┘ → 助力曲线 → 电机（峰值/反电动势/热）
```

## 2. 怎么打开

**默认关闭。** 关闭时行为与本层出现之前**逐位一致**，golden 不动
（`test_disabled_plant_changes_nothing` 断言的是 `==` 而不是 `approx`）。

车辆 profile / 实验 overrides 里：

```yaml
vehicle:
  overrides:
    steering_system:
      enabled: true
      architecture: r_eps        # 见 §3
      assist_map: default        # 见 §4
      assist_damping_ratio: 0.6  # 见 §5，别设成 0
      column:
        torsion_stiffness_nm_per_deg: 2.0
      motor:
        peak_torque: 5.5
      rack:
        coulomb_friction_n: 260.0
```

未给的字段保持默认，未知字段被忽略（与 `suspension` / `steering_geometry` 同规则）。

## 3. 架构

`sim4wis capabilities` 可列出。八种：

| id | 前轴 | 助力点 | 后轴 | 电机减速比 |
|---|---|---|---|---|
| `c_eps` | 机械 | 管柱 | — | 20 |
| `p_eps` | 机械 | 小齿轮 | — | 30 |
| `dp_eps` | 机械 | 双小齿轮 | — | 45 |
| `r_eps` | 机械 | 齿条 | — | 63　**默认** |
| `sbw` | 线控 | — | — | 63 |
| `eps_rws` | 机械 | 齿条 | 耦合 | 63 |
| `sbw_rws` | 线控 | — | 耦合 | 63 |
| `4wis` | 线控 | — | 独立四角 | 63 |

**减速比属于架构，不属于车辆。** 管柱蜗轮和齿条滚珠丝杠差 3 倍以上；
`r_eps` 的 63 是推导值：`2π·i_belt/lead × r_pinion = 2π·2.5/0.005 × 0.020`。

**架构决定能力，能力决定能问什么。** 问 `c_eps` 后轮相位会被拒绝并指向 `eps_rws`；
问 `sbw` 助力曲线会被拒绝并指向 `r_eps`。往线控前轴注入"助力丢失"同样会被拒绝——
那不是保守测试，是无意义测试。

机械前轴走被控对象链；线控前轴走**角度跟踪 + 路感合成**（§6），两者共用一个接口，
但线控**没有扭矩传感器通道**，因为硬件没有扭杆。

## 4. 助力曲线

标定工程师真正编辑的那个对象。**是表，不是公式**——因为标定就是逐点挪的。

- 断点：扭杆力矩 × 车速二维
- 表达在**小齿轮**上（N·m），与减速比、与架构无关 —— 同一份标定描述"给出同样帮助"
  的柱助力车和齿条助力车
- 内置 `default`（LS9 级重型 SUV）与 `none`（无助力机械转向基准）
- **拒绝随力矩下降的曲线**：驾驶员会感到"卡一下"，那是缺陷不是口味
- `scaled(factor)` 是 sweep 最简单的抓手，用来回答"这台车到底需要多少助力"

默认曲线的验算点：手力矩 3.5 N·m → 小齿轮 208.5 N·m → **齿条力 10.4 kN**（全锁停车）。

---

## 5. 阻尼不是可选项

**这是本层最容易踩的坑，写在最显眼处。**

助力是对扭杆扭转角的**比例反馈**，所以它把小齿轮惯量所对抗的等效刚度**乘上 boost 倍**。
默认曲线停车时 boost≈59，K_eff 从 115 涨到 6826 N·m/rad，而回路里的机械阻尼只有
0.41 N·m·s/rad —— **ζ = 0.0036**。

无阻尼的后果不是"手感差一点"，是**发散**：小齿轮反超方向盘 → 扭转角变负 →
助力反向 → 越振越大。本模型第一版就是这样，助力把停车手力矩从 96.5 **抬到** 174.3 N·m。

这正是量产 EPS 的 ECU 里必然有一项阻尼函数的原因。

`assist_damping_ratio` 默认 0.6，增益按局部 boost 调度以保持回路 ζ 恒定。
固定增益按停车工况选会在 100 km/h 过阻尼（ζ=1.34），那是另一种抱怨（转向发滞）。
真实标定用表，这个调度就是那张表的形状。

**别把它设成 0**，除非你就是想复现那个失稳（`test_an_undamped_assist_loop_diverges` 就是）。

## 6. 线控前轴

两个作动器，**只靠软件相连**：

- **前轮作动器** — 带宽受限跟踪 + 速率限。`angle_deviation` 被**监视**而非假定为小：
  它是发现作动器饱和/堵转/缺相的手段，也是 `angle_deviation` 失效模式的触发量。
- **反馈作动器** — 手力矩是**合成**的：路感项（齿条力经低通）+ 回正项（速度调度）
  + 阻尼 + 少量摩擦，最后被反馈电机能力钳位。

线控没有主销回正力矩传到手上，**不给回正项就是真的不回正**。

**已知限制**：路感低通目前是一阶，6 Hz 转折对 20 Hz 冲击只能衰减到 1/3.4
（−20 dB/decade 就这么多）。量产路感设计用更陡的滤波。
**要拿这个模型回答真实的冲击抑制问题，这是第一个必须改的地方。**

## 7. 新增通道

启用后可在 run 数据里取到（机械前轴）：

| 通道 | 含义 |
|---|---|
| `steer_hand_torque` | 方向盘手力矩 —— 本层的核心新增信号 |
| `steer_torque_sensor` | 扭杆传感器读数（仅弹性项，带饱和） |
| `steer_assist_torque` | 折算到小齿轮的助力 |
| `steer_motor_torque` / `_speed` / `_heat` | 电机工作点，选型用 |
| `steer_pinion_angle` / `steer_friction_torque` | |

线控前轴则是 `steer_road_feel_torque` / `steer_centring_torque` /
`steer_angle_deviation` / `steer_road_wheel_angle`，**没有** `steer_torque_sensor`。

## 8. 电机为什么按"限制"建模

按转矩级建模而非完整磁场定向驱动：车辆动力学时间尺度上电流环快一个数量级。
不白给的是**三个限制**，每一个都对应一种真实抱怨：

| 限制 | 症状 |
|---|---|
| 峰值转矩 | 停车打到底时助力饱和，最后一段变重 |
| 反电动势转矩-转速包络 | 紧急避让时快速输入跑赢助力，**手最需要轻的时候反而变重** |
| 热降额 | 连续第三次挪车比第一次重 |

**只按连续转矩选型的电机，稳态校核全过，这三条全挂。**

## 9. 作动器选型

```python
from sim4wis.steering.sizing import size_actuator
req = size_actuator(params)      # 走四个最恶劣工况，产出规格 + 判定
```

四个工况，每个都为暴露一件别的工况暴露不了的事而存在：
原地全锁（峰值转矩）· 连续挪车 ×3（热降额）· 低速大转角（综合负载）·
高速紧急避让（峰值转速 / 反电动势包络）。

**负载不是另建的模型**，而是从 `sweep_load_analysis` 插值出来的——和负载页同一个来源，
所以选型结果不可能和负载页对不上。

规格里的每个数字都带**是哪个工况决定的**。"6.9 N·m" 不是需求，
"6.9 N·m，来自原地全锁"才是。RMS 按占空比加权，不是把测试工况平均——
后者会把停车和高速巡航算成一样重要。

### 边际带已修复（驾驶员必须是柔性的）

曾经有一条"电机差一点够"的边际带会振荡，而选型恰恰工作在那里。根因不是数值：
助力饱和时电机把**包括阻尼在内**的一切都限幅掉，小齿轮就成了扭杆上一个 ζ≈0.03 的
质量块。真车此时不振荡，是因为**手臂是柔性、有阻尼、力量有限的**；而"强加转角"
是无限刚，什么都吸收不了。

放开转向柱自由度、把驾驶员建成弹簧-阻尼之后，整条带消失：

| 电机峰值 | 手力矩 | 电机转速 |
|---|---|---|
| 2.0 N·m | 17.98 | 1404 rpm |
| 4.0 | 10.32 | 1672 |
| 5.5 | 4.63 | 1539 |
| 8.0 | 4.66 | 1539 |
| 12.0 | 4.66 | 1539 |

单调，无处振荡，**欠配电机读起来就是"转向很重"而不是数值飞掉**。

`grip_stiffness` 默认 200 N·m/rad —— 这是**驾驶员主动保持目标角度**的等效刚度，
不是被动手臂阻抗（后者 10–30，会带来 22% 稳态 droop，因为被动手臂不会修正）。
稳定性在 20–400 全程保持，所以这个取值只按 droop 定：200 对应 2.1%。

### ✅ 峰值欠解析已按构造消除（多速率转向层）

柱模态约 10 Hz，指令角若在整个 5 ms 外步内保持不变（零阶保持），共振峰落在两个
采样点之间就被错过——峰值手力矩曾因此欠解析约 1/3（1.864 → 2.812 N·m，5 ms →
0.5 ms，RMS 只动 7%）。修复（Inc3 / D5）：转向层以 **0.5 ms 内步率**运行（10×），
指令在步内**线性插值**而非保持，车辆外环仍为 5 ms，输出在 5 ms 边界对齐回外环。
0.5 ms 内步峰值与 0.25 ms 参考差 < 2%（实测一致）。

直接调用 `SteeringPlant.step(dt)` 的代码仍然拿到的是零阶保持——只有车辆耦合
（`steering_link.plant_front_angle`）和选型模块做了插值。读峰值的直接调用方请用
`steering.plant.STEERING_INNER_DT` 量级的步长；读 RMS 的不必。

记录通道仍按 `record_hz` 采样：50 Hz 记录对 0.2 Hz weave 足够（每周期 250 样本），
被记录的是 5 ms 边界上的对齐输出，不受内步率影响。

## 10. 耦合上的一个已知事实

`state.rack_force` 由 `update_derived_outputs` 在 `model.step()` **之后**填充，
所以被控对象层看到的是**上一步**的负载。这是正常的耦合滞后（5 ms 下可接受），
不是缺陷。首步为 0，plant 从无负载起步。

写在这里是因为下一个读代码的人否则会花半天判断它是不是 bug。
