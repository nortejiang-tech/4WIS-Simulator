# v0.104.0 变更说明 — 物理数学修订 · 三种交互路径 · Agent 标准接口 · 双平台便携交付

> 发布日期：2026-09-09　·　基线：`bf0c187`（v0.103.0）→ 本版发布提交

v0.104.0 是一次面向可信仿真与可操作性的功能发布。它修复了会改变模型计算结论的物理、几何和数值问题，
把人工实时驾驶、脚本化工况和 AI Agent 整步调用统一到可追溯的结果流，并将 Agent 标准接口补入 macOS 和
Windows 便携包。它不包含实车、台架或独立商用仿真工具的相关性标定；这些边界仍在可信度矩阵中明确标记。

## 本版重点

### 1. 底盘动力学、几何与数值修订

- **车体力矩基准统一到质心。** 动力学和多体降阶模型不再把轴距中点的几何坐标直接当成质心牛顿–欧拉方程的
  力矩基准。通过质心的合力不会再产生伪横摆加速度；公开的车体坐标和显示坐标仍保持兼容。
- **四角轮胎/载荷物理边界收紧。** 载荷转移受轴荷约束并保持总支持力；离地或 `μ=0` 时接触力严格为零，
  消除了逐轮截零可能凭空增加可用附着的路径。
- **主销—齿条—电机力链恢复虚功一致性。** 硬点机构由隐式微分求 `ds/dδ`，几何投影不再被误作效率损失；
  电机效率只计一次。尺寸扫描同时暴露不可达/奇异区间，不通过虚增行程掩盖。
- **积分与状态生命周期可重放。** RK4 的中间阶段不再污染持久状态；轮速/转向状态按明确步进层更新；
  reset、录制、脚本结束和 Agent 会话的状态边界得到统一处理。
- **轮序、坐标和可视化一致。** FL/FR/RL/RR、车体 X 向前/Y 向左、质心与轴距中点的语义在后端遥测、
  几何示意和前端显示中使用同一约定。

这些修改改变了部分历史 golden 数值。基线只在独立的力矩平衡、虚功、非线性平衡点和步长对照通过后迁移；
阈值没有放宽。历史 run、旧手册和旧版便携包仍是历史结果，不能用来证明本版物理输出。

### 2. 三种交互方式与统一结果流

运行工作台现在把三类入口明确分开，并保证每条路径都能回到相同的 run/工件体系：

| 方式 | 用途与边界 | 结果 |
|---|---|---|
| 手动驾驶 | 键盘、浏览器 Gamepad、方向盘等实时输入；焦点丢失、页面切换、隐藏、断连和超时都会释放输入 | 实时轨迹/曲线、录制、结果库、CSV |
| 脚本工况 | YAML 动作序列拥有驾驶台输入；暂停、停止、失败和录制生命周期明确 | 可复现脚本 run、图表、全量导出 |
| Agent | 隔离的固定步长会话，GUI 输入永不改变其状态；请求按 revision 和完整 body 幂等 | 全量 CSV/JSON/ZIP、SVG 轨迹/图表、manifest、SHA-256 |

- Agent API 提供能力发现、创建、观察、推进、导出、关闭与异步 study；每次推进必须带完整控制、
  `expected_revision` 和 `request_id`。同请求不重复积分，不同 body 复用 request id 或过期 revision 返回明确冲突。
- 数值执行失败保留已接受前缀并标为失败，不 reset 后伪装成功；完整数据从导出的 run 取得，预览明确是抽样。
- 停止实时录制会保留样本，便于 CSV 导出或保存到结果库；新增「丢弃录制」动作显式清空停止后的缓冲，避免把旧数据误当成新工况，且不会重置车辆或删除已保存 run。
- 前端增加独立的模式栏、手动生命周期提示、脚本工作台、Agent 会话工作台、工件列表和图形预览；窄屏布局、
  输入焦点和页面切换已纳入浏览器回归。
- `docs/interaction_guide.md` 记录 REST/MCP 操作、单位、轮序、错误语义、输出格式和真实设备仍需验证的边界。

### 3. Agent 标准接口随便携包交付

此前便携构建只复制 `sim4wis` 主服务源码，遗漏独立的 `sim4wis_mcp` 进程，因此图形界面可启动而 Agent
标准入口并未真正随 zip 交付。本版补齐以下内容：

- `app/src/sim4wis_mcp/` 与 MCP Python SDK 随 macOS/Windows 包复制；普通 Web UI 与 Agent 使用同一嵌入式 Python 和数据根目录。
- 每包包含 `agent_mcp.command`（macOS）或 `agent_mcp.bat`（Windows）。它们设定包内 `PYTHONPATH`、
  以 stdio 运行 MCP 门面，并把参数透传给服务端。
- `agent_mcp.* --print-config` 输出当前解压绝对路径的 MCP 宿主 JSON。Windows 输出
  `cmd.exe /d /c <路径>\\agent_mcp.bat`，以正确处理 `.bat` 和带空格的解压路径。
- Windows 跨平台装配会显式 vendor `pywin32`：MCP 把该依赖声明在 Windows 平台标记后，macOS 构建机不会
  自动解析它。两个 Windows 启动器均加入 `win32`、`win32/lib` 和 `pywin32_system32`，验包器同时检查
  wheel 内容与导入路径，避免 zip 在 Windows 上才因 `pywintypes` 缺失失败。
- Agent 的 `verify_golden` 工具所需的受审查脚本、golden 基线、实验、车型、K&C、procedure 与目标数据也进入包；
  包不复制开发者的 run/study 历史，首次使用从干净的可写目录开始。
- `scripts/check_portable_package.py` 检查 zip 的路径安全与 CRC、当前源码 SHA-256、版本、UI/MCP 启动器、
  Agent SDK、支持文件、手册和数据；在原生平台还会从新解压的包启动嵌入式后端，验证 Web UI、Agent API 和
  `--print-config`。

### 4. 文档与可审阅性

- 图文用户手册新增三种交互方式、便携 MCP 配置与 Agent 会话/工件的使用说明；由当前生产构建实际截图生成。
- 物理评审、交互验收、ADR、STAGE 和 EVO-Coder 调用报告随源码发布，分别标出内部软件证据与实车/台架边界。
- README 的发布顺序增加便携包内容门禁，避免将“zip 存在”误判为双平台可用。

## 兼容性与迁移说明

- HTTP 与 MCP 是加法式扩展：旧 study 工具继续保留，新增 Agent 会话工具和工件发现工具。
- 因物理、载荷和力矩基准修订，旧 run 不能与 v0.104.0 run 混合做量化对比。需要比较时，应在同一版本、
  相同 project、场景、控制和输入下重新运行。
- macOS 包面向 Apple Silicon（`macos-arm64`），Windows 包面向 64 位 Windows（`windows-x64`）。两个包都不需要预装 Python 或 Node。
- 真实手柄/方向盘的浏览器设备识别、轴极性、踏板标定和力反馈，以及实车/台架相关性，不因软件回归通过而自动成立。
