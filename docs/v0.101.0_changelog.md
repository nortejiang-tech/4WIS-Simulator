## P0 — 纵向架构底座

**扭矩通道**：`ControlCommand.drive_torque_cmd` + `VehicleParams.longitudinal_mode`
（`speed_servo` 默认 / `torque`）。扭矩模式下轮速伺服完全脱开、积分清零。

**为什么必须有**：速度伺服到了目标速度就把扭矩收到阻力量级，所以
「弯中再给油把后轴推出去」「抬油门转向」「开放差速器丢牵引」这三类手感**在速度伺服下
拿不到**。而这三类恰恰是驱动形式最有辨识度的部分。

**实验速度与踏板解耦**（`mode_params["speed_target_ms"]`）——纵向版的 B3。
此前实验把目标速度绕道踏板（`throttle = v/v_max`），只在该映射恰好线性时才抵消；
一加踏板曲线、限速或功率包络就会静默移动全部 golden。放在 `speed_command` 里，
**所有策略自动生效**。

> 验收：默认模式下 golden **逐位不变**（全精度逐 KPI 比对，非"容差内"）。

## P1 — 附着状态与余量

后端只加派生量（Fx/Fy/Fz/μ/α/κ 早就在状态帧里）：

```
利用率   u = |F|/(μFz)          侧向余量 ΔFy = √((μFz)²−Fx²) − |Fy|
                                纵向余量 ΔFx = √((μFz)²−Fy²) − |Fx|
```

**过峰判据是这块的理论核心。** 利用率 0.95 在轮胎特性**上升段**可控、**过峰后**要走，
数值一样性质相反——只给余量会骗人。两个轮胎模型的峰值滑移都有闭式解，无需每步求根：
Pacejka 的峰值在固定滑移幅角 `x*`（只由形状因子决定，构造时解一次），而 `B ∝ 1/(μFz)`，
所以 `slip_peak = x*·C·μFz/刚度`，与 μFz 线性。数值校验与 argmax 完全吻合。

- **GripPanel**：四个摩擦圆，**半径 ∝ μ·Fz**——载荷转移直接看得见（转弯内侧圆缩小、
  制动前轮圆变大）；过峰时圆点变空心环；配车辆级 g-g 图
- **驾驶 HUD**：四根附着预算条（μFz 拆纵向已用/侧向已用/剩余）
- 利用率与余量进 recorder 通道，可事后画时间历程

## P2 — 驱动形式

`vehicle/powertrain.py`，四层：**需求 → 前后分配 → 差速器 → 限制（先每轮扭矩、再共享功率）**。

先扭矩后功率的顺序让 `drive_front_ratio` 在两个工况下自动正确：**起步**扭矩上限起作用，
纯前驱只有两个电机、确实只有四驱一半扭矩（真实硬件差别）；**中高速**功率上限起作用，
总扭矩恒为 P/ω，此时扫 λ 就是纯粹的分配实验。

**闭式验证**（`test_drivetrain.py` 34 项）：

```
后驱  a = μga/(L−μh)   加速载荷后移 → 自增强
前驱  a = μgb/(L+μh)   加速前轴卸载 → 自削弱
四驱  a = μg
```

μ=0.85/0.5 下实测均落在闭式解 10% 内且从不超过；残差 4–7% 是静态前束和外倾吃掉的
同一个摩擦圆——闭式解里没有定位参数。

一个反直觉但真实的点：**launch 加速度不随 λ 单调**。扭矩不受限时任何 0<λ<1 都能让两轴
同时饱和、结果都是 μg，只有两个端点落到单轴公式。测试按此写，并注明免得被"修"回去。

**扭矩转向白捡**：`kingpin_torque_terms` 里 `m_fx = Fx·scrub` 早就在，驱动力一不对称就有。

## P3 — 手动驾驶车速控制

难控速的直接原因是踏板轴跨 0–200 km/h。**速度上限重映射行程**（满行程=上限），
不是砍顶——砍顶会让大半行程变死区、反而更难控。另加可调油门曲线（低速段拉开）、
半圆弧车速表（带巡航目标刻度）。验证通道 `speed_target_ms` 不受限速影响。

## P4 — 底盘调校：让默认车具备量产车的不足转向

新增的 `scripts/driving_dynamics_review.py`（18 项标准客观指标）测出
**不足转向梯度 K = 0.07 deg/g**——中性转向。量产车按设计都是 1–4：极限时先推头
（可读、可修正）而非先甩尾；K≈0 还意味着横摆增益 `v/(L+K·v²)` 随车速线性增长不封顶。

根因：`K = W_f/C_f − W_r/C_r`，51/49 轴荷配四轮同一个 `tire_c_alpha` ⇒ K ≈ 0。
**不是 bug，是参数没调过。**

- `tire_c_alpha_front_scale = 0.80` / `rear_scale = 1.20`（新增）→ **K = 1.49 deg/g**
- `roll_stiffness_front_frac = 0.60`（新增）：侧向载荷转移改按侧倾刚度分配；多体的
  防倾杆从「纯整车力矩」改为每角的力——此前它只阻侧倾、不转移载荷，是项目遗留清单上
  缺的机制。**但它对线性区的 K 几乎无影响**（c_α ∝ Fz^0.8 下现实转移量只损失轴能力
  不到 1%），它管的是极限行为。

> ⚠ 这是**调校选择，不是实测**。OEM 不公布轴侧偏刚度。两个参数置回 1.0 / 0 可逐位
> 回到 v0.100.0 基线（已验证）。

## 驾驶动态真实性评审 — 18/18

`scripts/driving_dynamics_review.py`，报告见 `docs/reports/driving_dynamics_review.md`。

| | 实测 | 参考区间 |
|---|---|---|
| 0–100 km/h | 4.55 s | 4–8 |
| 100–0 制动距离 | 44.8 m | 36–50 |
| 制动踏板线性度 R² | 1.000 | >0.95 |
| **不足转向梯度 K** | **1.49 deg/g** | 0.5–6 |
| 侧倾梯度 | 5.79 deg/g | 3–8.5 |
| 极限侧向加速度 | 0.867 g | 0.65–0.95 |
| 极限前/后轴侧偏比 | 1.67 | 1.05–3（>1 = 推头先到） |

**这是可信性评审，不是验证**：对照的是该车型级别的公开典型区间，不是这台车的实测数据，
与 `independent_reference: GAP` 属同一范畴。对照构型用**前轮转向 + 多体 + 扭矩模式**——
4WIS 是研究对象，零侧偏四轮转向车本来就不该像普通车。
