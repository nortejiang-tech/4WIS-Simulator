## 工作包 A — 制动系统

### 核心设计：方向意图踏板模型

采用**前端方向意图状态机 + 后端纯物理语义**分层：

- **后端 `DriverInput`**（纯物理）：`throttle∈[0,1]`（驱动）+ `brake∈[0,1]`（摩擦制动踏板）+ `gear∈{-1,0,1}`（R/N/D）+ `steering` + `handbrake`。
- **前端** `KeyboardInput` 内置方向状态机：键盘 W/S、手柄 LT/RT、方向盘踏板统一汇入同一套解析逻辑（符合"策略也用在手柄和方向盘上"的要求）。

**踏板语义（用户决策）：**

| 当前状态 | 按 W | 按 S |
|---|---|---|
| 前进中 (D) | 加速 (throttle↑) | 摩擦制动 (brake↑) |
| 停住 (|v|<0.3) 且 S 松开后**再按** S | — | 切倒车 (R) |
| 倒车中 (R) | 摩擦制动 (brake↑) | 倒车加速 (throttle↑, gear=R) |
| 停住且 W 松开后**再按** W | 切前进 (D) | — |

- 停住时按住的制动键**不自动切换方向**（必须松开重按，避免误操作）。
- **空格 = 手刹**（驻车制动，后轴固定制动扭矩）。
- `R` 键保持 reset 不变（文档和 e2e 都依赖）。

### 新增/改动

- **`core/state.py`**
  - `DriverInput`：`throttle` 语义收窄为 `[0,1]`；新增 `brake`、`gear`；`throttle_signed` 只读属性（=throttle−brake）兼容旧脚本读取。
  - `VehicleParams` 新增：`brake_torque_max=12000.0`、`brake_bias_front=0.65`、`brake_tau=0.08`、`v_max_reverse=5.0`。
  - `VehicleState.wheel_locked: np.ndarray[bool]`（抱死标志，推前端 HUD）。
- **`controller/longitudinal.py`（新增）**：`speed_command(params, driver, v_actual, dt, mu_eff) -> v_cmd` + `apply_brake_command(cmd, driver, params)`。两层纵向控制：
  - 第 1 层（所有模型共用）：`(throttle, brake, gear) → v_cmd`，制动减速率上限 `brake·μ_eff·g`，运动学模型也有限制动（不再瞬间停车）。`mu_eff` 由各策略传入 `state.mu_avg`，**不是**默认值——否则运动学模型在冰面上和干沥青刹得一样狠，正是本包要修的毛病。
  - **权限顺序：刹车 > 档位 > 油门**。刹车压过油门（左脚刹车、踏板重叠时不得弹射）；也压过档位选择（空挡里服务制动照样有效）。松开刹车后才轮到档位决定：N 滑行、D/R 各自加速。手刹以后轴份额并入这层，所以只拉手刹也能命令停车。
  - 第 2 层（dynamic/multibody）：真实摩擦制动扭矩，见下。
- **摩擦制动扭矩**（`model_core.friction_brake_torques`，两个模型共用一份实现）：
  - `T_i = brake_filtered_i · brake_torque_max / 2`，其中 `brake_cmd_i` 已含轴分配（前轴 65% / 后轴 35%）。`brake_torque_max` 是**整车**口径（对标 m·g·r ≈ 11237 N·m），所以要除以同轴两个轮；漏掉这个 /2 会让整车力矩翻倍，约 0.3 踏板就全轮抱死。
  - `brake_tau` 一阶滤波（液压/EMB 响应）。
  - **抱死是特性**：卡钳按踏板要求施加力矩，接地点只能反作用 `r·μ·Fz`，多出来的部分把车轮本身减速到 0 → 全滑移、摩擦椭圆吃光侧向力 → 抱死时转向失效（无 ABS，这是要能演示的现象）。**注意不能把施加力矩钳到接地上限**——那样车轮总能找到平衡滑移率，真正的抱死永远不会发生（初版就卡在 κ≈−0.08 一边滚一边被报成"抱死"）。
  - **保持力矩**：ω≈0 时 `sign(ω)` 没有信息，改按车轮接地速度方向给力矩。否则制动力矩恰好在车轮完全抱死的瞬间消失，车会从全踏板底下爬走（实测低速爬行 8.5 s），手刹也拉不住坡。
  - **零穿越钳制**（`model_core.semi_implicit_wheel_spin`）：制动力矩把 ω 拉过零时钳到 0，防反向抖振。只对**制动**力矩生效——电机是应该能把车轮驱动过零的，倒车就靠这个。
  - **伺服脱开**（`wheel_servo.py`）：`brake_cmd>0.02` 时伺服输出 0、积分清零。不能只钳到 `≤0`：它是速度伺服，钳完仍会满力矩追踪衰减中的 `v_cmd`，而那条支路与踏板无关。
- **倒车**：`gear=-1` → `v_target = −throttle·v_max_reverse`（5 m/s 限速）。
- **驻车制动**：`handbrake=1` → 后轴施加其自身份额 `brake_torque_max·(1−bias)/2` 每轮（不是满钳，否则拉手刹比全力踩刹车还狠），并在 `speed_command` 里作为制动需求下限——两者缺一，手刹都拉不住全油门。
- **协议**：`ws.py` 透传 `brake`/`gear`；状态帧 `driver` 回显 + 每轮 `locked` 标志（真正抱死滑移时为 true；静止驻车不算抱死）。
- **前端**：方向意图状态机、`ws.ts` 的 `setDriver` 签名扩展、HUD 显示档位(D/N/R)/刹车/手刹/抱死。
  - 键盘与手柄/踏板**合并成一次**状态机求解（每帧一次），不再在推送块里用陈旧输入再走一遍。
  - 倒车中按 W 判据用 `movingWith`（倒车时 vx<0 本就是"顺行"），初版误用 `movingAgainst` 导致该分支恒假、W 完全没反应。

### 向后兼容（必须）

- `set_driver` 收到旧协议 `throttle<0` 且**未显式给 brake** 时，自动转换为 `brake=−throttle, throttle=0`；收到**非负** throttle 时同样清零 brake——旧协议这一根轴同时拥有两个通道，没有别的办法松刹车，不清就会永久粘住。
- `input/script.py` 的 `brake` 动作改为直接发 `brake=1.0`（不再 `throttle=-1`）。
- `user_python` 暴露给脚本的 driver dict 新增 `brake`/`gear` 字段。

### 物理验证（实测，dynamic 模型，干沥青 μ=0.85，60 km/h→0）

| 踏板 | 制动距离 | 平均减速度 | 抱死时长 |
|---|---|---|---|
| 0.1 | 125.3 m | 1.11 m/s² | 0 s |
| 0.2 | 67.3 m | 2.06 m/s² | 0 s |
| 0.4 | 35.4 m | 3.92 m/s² | 0 s |
| 0.6 | 24.3 m | 5.71 m/s² | 0 s |
| 0.8 | 18.7 m | 7.43 m/s² | 2.0 s |
| 1.0 | **17.3 m** | 8.01 m/s² | 1.9 s |

- 理论极限 v²/(2μg) = 16.7 m；全力制动 17.3 m，多出的部分来自 `brake_tau` 建压过程和末段抱死滑移（滑动摩擦略低于峰值 μ），符合预期。
- 停车耗时 2.0 s（理论 2.0 s），**无低速爬行、无倒溜**（vx 全程 ≥ 0）。
- 抱死只在 0.8 以上出现——既能演示"无 ABS 会抱死"，又留出完整可用行程。
- 附着相关（全力制动）：μ=1.0 → 15.7 m，0.85 → 17.3 m，0.5 → 28.1 m，0.3 → 45.4 m，0.15 → 86.4 m，逐点贴合 v²/(2μg)。**运动学模型同样跟随 μ**（`state.mu_avg`）。

> 关键设计点：制动时轮速伺服**完全脱开**（输出 0、积分清零），而不是"钳到 ≤0"。
> 它是个*速度*伺服，钳到 ≤0 之后仍会以满 `torque_limit` 追踪正在衰减的 `v_cmd`，
> 而这条支路与踏板无关——初版就是因此让 0.2 与 1.0 踏板给出同一次 11 s 全轮抱死滑行。

### 验收

- `backend/tests/test_brake.py`：**22 项**测试（踏板行程单调、全力制动距离贴近理论、不爬行不倒溜、两个模型都随 μ、抱死只在高踏板出现且真的到 κ→-1、手刹拉得住全油门、刹车优先于油门与档位、旧协议往返、伺服脱开）。

## 工作包 B — 转向映射

### 问题

`ideal_ackermann` 把归一化输入线性映射到曲率，与车速无关。后果：60 km/h 时方向盘只要转 ±12°（270° 盘全行程的 4.5%）轮胎就饱和，**再打没有任何额外响应**——用户感知的"不够灵敏"实际是"可用行程塌缩到前 5%"。

### 三层映射（`controller/steering_feel.py`，新增）

```
第 1 层  方向盘角      θ_sw = steering · (steer_wheel_range / 2)
第 2 层  可变传动比    δ_raw = θ_sw / i(v)     i(v) 在 i_low…i_high 间随速插值
第 3 层  横向加速度软限幅  δ_eff = δ_allow · tanh(δ_raw/δ_allow) · g(s)
```

**为什么必须可变传动比**：540° 方向盘配真实 15:1 传动比，满打只有 ±18° 前轮角，绕桩开不了；固定低传动比在 100 km/h 又太贼。

**传动比按盘径自动推导**：`i_low` 取 `(range/2) / steer_limit`，使满行程正好打到机械极限——540° 盘得 7.71:1，270° 盘得 3.86:1，900° 盘得 12.86:1，三者手感完全一致。`i_high = 3.5 · i_low`。写死一个数值是错的：初版 `i_low=4.0` 是按 270° 盘算的（270/2/4 = 33.75° ≈ steer_limit），而默认盘是 **540°**，同样的比值要 67.5°，是机械极限的近两倍——满舵在 54% 行程就到头，低速增益成了旧版的 1.85 倍。

**第 3 层必须是软限幅，不是 clamp**：硬 clamp 虽然把 a_y 压住了，却原样复刻了本层要消灭的死区——初版实测可用行程 10 km/h 只有 54%、60 km/h 14%、100 km/h **6.8%**，比它要修的那台车更糟。现用 `tanh` 平滑压缩保证全行程严格单调（打到底之前每一度都还有响应），再乘归一化因子 `g(s) = min(s,1)/tanh(s)`（`s = δ_raw_max/δ_allow`）把满行程精确落在 `min(δ_raw_max, δ_allow)` 上：低速抓地力富余时 `g` 让满舵仍能到机械极限（裸 tanh 会渐近，白丢约 10% 锁量，最小转弯半径 3.04→3.4 m）；高速或冰面上 `g→1`，满舵落在附着极限。`g ∈ [1, 1.31]`，**中心增益不会被削**。

`VehicleParams` 新增：`steer_wheel_range=540.0`、`steer_ratio_low=0`（0 = 自动）、`steer_ratio_high=0`（0 = 3.5×低速比）、`steer_ratio_v_ref=22.0`、`steer_ay_ref_frac=0.9`。

### 策略衔接

- `ideal_ackermann`：`κ_cmd = tan δ / (L/2 + (tf/2)·|tan δ|)`，即 `_max_curvature` 的逆，保持零侧滑 ICR 语义不变。
  **不能用自行车公式 `tan δ / L`**：本策略两轴对称转向，ICR 在过车辆*中心*的横轴上，力臂是 `L/2` 不是 `L`。
  用自行车公式会把车悄悄变成前转向车——满舵 κ 从 0.3291 掉到 0.2216，最小转弯半径 3.04 m → 4.51 m（+48%）。
  δ 是*内侧*轮角，而"内侧"随转向换边，所以关系必须奇对称（半轮距项恒为增大半径），否则右转比镜像左转更紧、外轮越限、四轮不再共心。
- `rear_wheel_steer`：steering → δ_eff 前轮角（与 ideal_ackermann 一致的手感）。
- `fault_reconfig`：本就直接用 κ_max 映射，不走手感层（重构控制器测的是车辆）；已支持 `steer_raw_rad`。
- `crab`（蟹行角）/ `zero_radius`（只用符号）：**不走此链路**（代码注释写明理由）。

### B3 验证单位解耦（关键架构决策，前置）

验证实验的转向幅值从归一化 `[-1,1]` 迁移到**物理单位** `front_deg`（前轮角度），让 session 绕过驾驶员手感层、直接下发前轮角（通过 `mode_params["steer_raw_rad"]`）。

> 验证实验测的是**车辆**，不该被**驾驶员输入映射**的调参影响。这一步让以后每次调手感都不再打掉验证基线。

- `experiment/schema.py` 的 `SteerProfile` 新增 `unit: "normalized" | "front_deg"`，并按单位分别校验幅值（normalized 仍限 ±1，否则 50 也能填进去变成永久满舵）。
- 不支持 `steer_raw_rad` 的策略遇到 `front_deg` 会**报错**，而不是静默把 steering 置 0 跑出一条直线当基线。
- `front_deg` 分支原地写入 `mode_params`，不再每帧重建——重建会丢掉实验级参数（`fault_reconfig` 的 `fault_wheel`/`fault_time`/`detect_delay` 都在那里），静默把缓解控制器按默认值重新武装。
- 两个 golden 实验 + 两个解析基准 + 安全研究脚本都改为 `front_deg`，振幅按本策略几何换算（`κ_max=0.3291/m`，`δ = atan(κ·(L/2)/(1-|κ|·tf/2))`）：
  - `step_steer_60kmh`: 0.05 → **1.508559°**
  - `iso3888_dlc_60kmh`: 0.06 → **1.814818°**
  - `curve60` / `dlc60`（安全研究）: 0.05 / 0.06 → 同上两值

### 前端

- 参数面板暴露 `steer_wheel_range` / `steer_ratio_low` / `steer_ratio_high` + 制动参数（`brake_torque_max` 等）。
- **方向盘硬件预设**：PC 盘 540° / Dolio R270 270° / 900° 一键切换；**换盘只需改这一项**，传动比自动跟随。
- HUD 读数：`方向盘 θ_sw° · i X:1 · δ Y°`。传动比和 δ_eff 由**后端下发**而非前端复算——前端复本看不见 μ 软限幅，会报出车辆根本没收到的角度，而这恰恰是"让传动比起作用可见"最需要诚实的地方。
- 状态帧新增 `steer_wheel_range` / 解析后的 `steer_ratio_low`/`high`/`v_ref`、以及每帧 `driver.steer_ratio` / `driver.steer_delta_eff_deg`。
- `ExcitationPanel`（开环激励）改走 `steer_bypass_feel`：开环转向测试测的是车辆，幅值不该被手感层改写——否则 60 km/h 以上旋钮过了 0.14 就没反应，且幅值随车速漂移。

- 两个解析基准（`analytic_*_30kmh`）同步切 `front_deg`；`reference.csv` **无需改动**——修正后的角度精确复现原曲率，这正是换算正确的判据。manifest 的 `yaw_gain` 参考值按新单位更新为 5.20755。
