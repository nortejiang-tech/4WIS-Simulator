## 修复（Fixed）

### 车速与 HUD 可读性

`Speedometer` 的数字用的是 `fill: var(--fg)`，而 `--fg` 在整个样式表里不存在。
CSS 自定义属性替换失败不会报错，只会让该属性退回初始值 —— SVG 的初始 `fill` 是
**纯黑**。页面上实测 `getComputedStyle` 返回 `rgb(0, 0, 0)`，叠在 HUD 的深色面板上
等于隐形。这类失败是静默的，所以现在所有取主题色的地方都带字面回退值。

同一族的第二个问题：`.canvas-hud` 把面板底色写死成 `rgba(17,24,39,0.85)`（深色），
里面的文字却取主题变量。切到浅色主题时 `--text` 变成 `#0f172a`，于是**整块 HUD
（车速、ψ̇、μ、位姿）都是深底黑字**。面板底色现在跟随主题，μ 读数的"正常"档也从
写死的近白改成主题色。

顺带：`--surface` / `--bg` 同样从未定义（6 处调用点，背景静默变透明），在
`styles.css` 里补为 `--bg-2` / `--bg-0` 的别名。

### 3D 视口的运动重建

后端推送间隔是 `round(dt_push / dt_sim) = 3` 个仿真步，即 **15 ms / 66.7 Hz**，
而不是常量读起来的 60 Hz。页面实测到达间隔：均值 15.0 ms，p90 16.7，p99 19.6，
min 9.1，max 20.7。原来的渲染把 `state.pose` 直接写进变换矩阵，于是世界运动被量化
到"哪一帧恰好收到包"：66.7 Hz 对 60 Hz 显示拍频出 ~6.7 Hz，每秒六七次一帧重复、
下一帧跨两步，再叠上 ±5 ms 的到达抖动。

轨道视角下这只是远处车身轻微抖动；**车顶视角整个世界刚性绑在位姿上，同样的误差
就变成满屏顿挫** —— 这正是"尤其是车顶视角"的由来。

新增 `frontend/src/view/renderPose.ts`：每个渲染帧用样本自带的车身速度
(vx, vy, ψ̇) 把位姿**航位推算**到渲染时钟，再对每次新样本带来的厘米级修正做残差
平滑；外推量额外加上平滑器自身的离散滞后 `dt·(1−α)/α`，两者抵消，所以不是拿延迟
换流畅。车身、车轮、ICR 标记、跟随相机、车顶相机共用同一次重建结果。

这层与推送频率解耦：即使后端掉到 20 Hz（慢主机、粗糙的 OS 定时器），画面仍然连续。
样本年龄按**实测的钟差**计算而不是假设为零 —— 假设为零会重新制造出同一个锯齿。

车轮转角同样走重建（用相邻样本估的 δ̇ 外推）：原来 δ 每 15 ms 一跳，转向最快时
每跳好几度，这是"车轮动作不自然"的另一半。

单元测试（`renderPose.test.ts`，8 项）钉住效果：稳态每帧位移波动从 ±100% 降到
< 2%，同时最大位置误差 < 5 cm(18 km/h) / < 25 cm(90 km/h)；含首帧 `dt = 0`
和长时间切走标签页两种退化帧时的守卫。

### 3D 深度精度（针对 Windows 16 位深度回退）

`near/far` 从 0.3/2000（比值 6667:1）收到 0.4/1200（3000:1）。地面是一叠近共面的
面（地平线 −0.05、网格 0、路面 0.01、人行道 0.02、标线 0.05、轨迹 0.06），车顶
视角几乎是贴地视线，是深度分辨率最坏的情形。24 位深度（Metal / ANGLE→D3D11）吃得下，
部分 Windows 驱动仍会回退的 16 位深度吃不下，表现为地面抖动 ——
见 `scripts/render_verify/README.md`。**该项无法在 Mac 上复现验证**（本机 24 位）。

同时修掉一个既有缺陷：地平线圆盘固定在世界原点、半径 1400 m，**车开出原点 1400 m
之后地平线整个消失**（实测 8 km 处车顶视角下方只剩背景色）。现在圆盘跟随相机，
半径 900 m。

### 转向初始动作

键盘转向原来用的是和踏板同一个一阶滞后（τ = 0.18 s）。这个形状对方向盘是反的：
**按下瞬间速率最大** —— (1−0)/τ = 5.6 /s，在默认 540° 方向盘上约 1500 °/s，是紧急
避让的速率 —— 之后指数衰减。60 Hz 下第一帧就跳 8.9% 行程（≈24° 方向盘），剩下的
路程越走越慢：0.18 s 到 63%，0.41 s 到 90%，0.83 s 到 99%。

改为限速率（梯形）曲线，见 `frontend/src/input/steerRamp.ts`：速率本身有加速度，
先建立、再匀速、最后减速到位 —— 方向盘有角加速度，而不是阶跃响应。

    第一帧（60 Hz）  a·dt² = 0.0044（≈1.2° 方向盘），比原来轻 20 倍
    到全锁          0.19 s 建立 + 0.15 s 匀速 + 0.19 s 收尾 ≈ 0.52 s

中段节奏与原来接近（0.18 s 时 0.54 vs 0.63），所以键盘并没有变难开；改变的只是
运动的两端，而那正是"假"的来源。回正仍是指数衰减 —— 那个形状本来就对，回正力矩
随角度下降。10 项单元测试锁住形状：起步从静止、第二帧比第一帧走得远、中段恒速率、
到位不超调不振荡、反打时速率过零而非跳变。

### 轮胎 μ(Fz) 作用在力路径上

`load_sensitive_mu` 原来只在 `_finalize` 里调用，那条路径驱动轮速和诊断；车身力来自
`_derivatives`，仍然把名义 `wheel_mus` 传给 `tire.forces`。所以这个机构几乎是惰性的：
极限以下只通过轮速耦合漏出 ~5e-7，到了极限，用名义 μ 画出的摩擦圆报出 1.10 的利用率
——一条跑在自己摩擦圆外面的轮胎。现在在每个 RK4 阶段看到的载荷上生效，抱死判据和
抓地诊断用同一个有效 μ，四个消费方口径一致。

6°/80 km/h 实测：极限 a_y 8.46 → 8.08 m/s²，util_max 回到 1.0000，侧倾刚度分配
对极限平衡的权限 0.0051 → 0.0211（4 倍）。同时更正了参数文档里的一处说法：μ(Fz)
**不**赋予侧倾分配对线性区不足转向梯度的权限（K = W_f/C_f − W_r/C_r 是侧偏刚度量，
μ 不进入），它是极限机构。`k = 0` 与 `σ = 0` 仍是 no-op，golden 逐位一致。

### 两份转向研究报告

- `docs/reports/steering_decoupling_value.html` — **解耦转向自由度价值量化**。
  逐级阶梯（前轮 → RWS → 4WIS）+ 六种后轮控制律逐条讲解：架构定义、理论推导
  （自行车模型、零质心侧偏角比例与参考横摆角速度）、方法（标定、指标定义、相关法
  相位估计、稳定判据），14 张图、12 张表、12 个公式，每张图配"怎么读"。
  过程中理论抓出两个真缺陷：`axle_cornering_stiffness()` 对前后轴都返回
  `2*tire_c_alpha`、忽略车辆实跑的 0.80/1.20 分配，导致 K 差 12 倍、k(v) 在
  120 km/h 过指令 54%；以及噪声敏感度的实测结论与此前断言相反。
- `docs/reports/rear_steer_angle_range_value.html` — **后轮转角范围价值**，
  需求曲面推导 + 角度包络单独研究。
- 复现脚本：`scripts/decoupling_study/`、`scripts/rear_angle_study/`。
- `kc_profiles/ls9_estimate.yaml` — LS9 K&C 估计标定。
