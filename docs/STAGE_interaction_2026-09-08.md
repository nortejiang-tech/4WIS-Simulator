# 三种交互与统一结果交付

## 授权与基线

用户要求在第一轮物理修正基础上优化手动、脚本和 Agent 交互；Agent 优先，保留图形、全量数据和图表输出。沿用 `codex/astra-dynamics-review`，上一轮所有未提交改动属于本轮基线，保留不回退。当前源码快照、哈希和已有 diff 位于 `/tmp/4wis-interaction-review/`。

已读依据：用户全局 AGENTS.md、Personal/ENGINEERING-METHODOLOGY.md、实际 App/输入循环、Simulator/SimSession、REST/WS、Recorder/run store、study 与 MCP 实现。旧 `agent_interface_design.md` 包含未实现设计，不能当成功能事实。

## 目标与设计

1. 手动驾驶：输入只作用于驾驶页面；失焦/离开驾驶台释放输入；停止、暂停和控制来源可见。保留现有键盘方向意图与手柄/方向盘映射。
2. 脚本工况：实时动作脚本独立入口，与隔离批量试验明确区分；不再藏在数据工具中。保留现有脚本格式与实验定义。
3. Agent：新增版本化、可发现的隔离会话接口，create → observe → step → export。固定步长、严格输入、修订号、请求去重、明确错误与资源上限；不自动争夺人工实时 Simulator。
4. 结果：持久 run 是共同交付对象。提供完整 CSV/JSON、元数据/通道说明、图形轨迹与图表 SVG，以及现有分析页入口；预览降采样不得伪装全量。
5. MCP 保留现有工具，增加会话控制与异步研究作业入口、状态轮询和结果工件发现；不以长阻塞调用作为唯一接口。

Agent 会话调用同一车辆/控制/力链，不另写物理模型。输入是结构化数据，不开放任意代码。短闭环会话按 API 公布的步数/时间/会话数上限执行，长研究继续使用已有 study/batch。

## 路由与信任门

状态生命周期、共享输入仲裁、结果落盘与标准协议由 ASTRA 处理。EVO Coder 只承担隔离临时目录中的三模式导航组件（最多 2 production 文件 + 1 聚焦测试），输入为 Planner 写定的接口/文案及已核实编译配置；不暴露旧研究文档、插件或凭据。独立审阅和真实浏览器验收后才复制新文件进入项目。

## 验收

- 独立会话不改变人工实例；分批推进与一次推进一致；重复请求不重复积分，过期修订号拒绝；非法/超限参数拒绝，失败不伪装重置成功。
- 每个导出数据包含完整样本、通道与出处；CSV/JSON/图形来自同一 run，预览标明采样；重试导出不重复创建 run。
- MCP 实际 stdio 客户端完成建会话、推进、观察、导出；错误有结构化结果。
- 浏览器验证三种入口、键盘焦点、脚本加载/启动/停止、Agent 会话图形/图表/导出、分析页衔接，桌面与窄屏无主要溢出。
- 后端全量、前端单元/类型/构建、原有与新增浏览器回归通过；模型黄金实验复核按核心步进变化决定。

使用 frontend-testing-debugging 工作流。Browser plugin not available，沿用已安装 Playwright；截图/临时 QA 脚本放 `/tmp/4wis-interaction-review/`。
