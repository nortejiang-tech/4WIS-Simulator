# 目标层指南 —— 从"跑出一堆曲线"到"对着目标判定"

> 面向系统工程师。前置：[study 层指南](study_guide.md)、[转向系统指南](steering_system_guide.md)。

一个仿真工具最容易停在的地方，是**能算但不判**：结果一张表，曲线一大把，
"所以呢"要靠人来回答。目标层补的就是这一步 —— 一张符合性表回答
**这套转向配置达标了吗**。

```bash
sim4wis targets list                    # 库里有什么
sim4wis targets show eps_actuator       # 一套要求的全文与依据
sim4wis targets check eps_actuator      # 跑一次选型走查并判定
```

退出码：符合 `0`，不符合或覆盖不全 `2`。可以直接挂进 CI。

---

## 1. 它和 study 的 `criteria` 不是一回事

两者长得像，回答的问题完全不同，混在一起是阈值无法追溯的开始。

| | `criteria` | 目标集 |
|---|---|---|
| 属于 | **一个问题** | **一个产品** |
| 生命周期 | 随研究写、随研究扔 | 有名字、有版本、长期维护 |
| 阈值为什么是这个数 | 为了让这一个论断可证伪 | 有出处、有归口、可被评审 |
| 复用 | 不复用 | 每次研究、每套配置都引它 |
| 例子 | "后轮权限超过 6° 会不会带来超调？" | "本项目原地泊车手力矩不得高于 5 N·m" |

两者可以同时出现在一份 spec 里：**criteria 说这次研究有没有回答它的问题，
目标集说这套配置能不能交付。**

## 2. 三条设计约定

### 每条要求都是一个"带"

单边限值只是半开的特例，不是另一种东西。这不是抠字眼：中心区力矩梯度**太小**
和太大一样是问题，回正力矩太强和太弱一样是问题 —— 一个只会写"小于"的 schema
会把这类需求悄悄逼成它的单边一半。

```yaml
limit: "<= 5.0"          # 半开
limit: ">= 0.4"          # 半开，另一侧
limit: "abs <= 1.0"      # 对称
limit: [0.15, 0.60]      # 闭带，两侧都是要求
```

### `target` 和 `limit` 是两个东西

`target` 是想达到的，`limit` 是不能越过的。合成一个数就丢掉了"这次是没问题"
和"这次是侥幸"之间的区别。落在两者之间判 **边际（MARGINAL）**，仍算符合，
但评审读它和读"达标"是两回事。

### `source` 必填

需求评审的第一个问题永远是"谁说的"。没有出处的数字是偏好，不是要求，
会被任何想推翻它的人推翻。schema 直接拒绝存这样的数字。

## 3. 四种判定，第三种最重要

| 判定 | 含义 |
|---|---|
| **达标** MET | 落在 target 带内 |
| **边际** MARGINAL | 在 limit 内、target 外 |
| **超标** VIOLATED | 越过 limit |
| **未评估** NOT EVALUATED | 本次没测到，或测量值不可信 |

**「未评估」不是通过。** 一个目标集覆盖整个产品，任何一次研究或选型只跑得到
其中一部分。把没测的部分判 FAIL，表就没人看；判 PASS，表就是假的。所以
**覆盖率是一等输出**，集合级判定分成：

- **不符合** —— 有东西超标了（超标压倒缺口：失效了就是头条，缺什么另说）
- **覆盖不全** —— 没有超标，但有强制要求没被评估
- **符合** —— 全部强制要求都评估过，且都在限值内

`severity: should` 的条目会列出来、会计数，但不参与集合判定。

### 不可信的测量不会被判定

选型模块自己声明过：手力矩到上限之后，车轮没有到达指令角度，那些峰值描述的是
一次没有发生的操作。符合性表**不判定**这样的数字 —— 它会报"未评估"并把原因
带上。把这种结果判绿，等于把一个不能用的结果洗成一条签过字的需求，
比没有这张表更糟。

## 4. 余量怎么算

余量是**距限值的相对裕度**，正数表示还有富余，0 表示正好压线，负数表示超了。

- 单边限值：未用掉的比例，`(limit − v) / |limit|`
- 闭带：半带宽的未用比例 —— **带中心 100%，带边 0%**
- 无定义时留空（限值为 0、等式要求、无界）：报 `inf` 或"除以零的百分比"
  是编数字，与报告里 Δ% 在基准为 0 时留空是同一条规矩

"达标"和"以 2% 的余量达标"是两种工程处境，只有一种扛得住公差堆叠。
所以表里给的是余量，不只是判定。

## 5. 写一个目标集

放一个 YAML 到 `targets/` 目录（或 `$SIM4WIS_TARGETS_DIR`）：

```yaml
name: my_programme
version: 1
title: XX 项目转向要求
applies_to: 2.9 t SUV，R-EPS          # 必填：不说明适用范围的要求集，
owner: 系统工程                        #       迟早会被用到它没写过的东西上
entries:
  - id: parking_effort
    metric: peak_hand_torque_nm
    at: "scenario == parking_full_lock"
    limit: "<= 5.0"
    target: "<= 4.0"
    unit: N·m
    source: 竞品实测 3.8–4.6 N·m
    rationale: 原地全锁是手力矩最恶劣点，也是用户最常抱怨的一点
```

完整示例：[`docs/examples/targets_vehicle_response.yaml`](examples/targets_vehicle_response.yaml)。

`at` 用的是和 study `criteria` 完全一样的工况选择器 —— `all`，或用
`and` 连接的等式过滤（`speed_kmh == 100 and mu == 0.9`）。一种比较语言，
不是两种。

**版本是硬约定。** 文件里声明一个已经内置的 `name@version` 会被直接拒绝：
一个被引用的需求版本不能指向两份不同的文档。改了就 bump。

## 6. 在 study 里引用

```yaml
study: rear_authority
model: multibody
targets: my_programme@1        # 或不带版本，取最新
...
```

`--dry-run` 会在**跑之前**告诉你哪些强制要求本次不会被覆盖：

```
! 目标集 my_programme@1 有 2 条强制要求的指标本研究不计算，
  将判为「未评估」：onc_torque_deadband_deg, return_residual_angle_deg
```

跑完之后，结果里带 `compliance` 块，报告里多一节"目标符合性"和一张"目标依据"表。
报告渲染的是**存下来的那次判定**，不会拿今天的目标库重算 —— 会悄悄重算的
符合性记录没人能审。

## 7. 内置的两套

### `eps_actuator` —— 今天就能判

对着一次选型走查判定，跑完就有结论。它就是作动器规格书写成需求的样子。

默认 LS9 + 8 N·m R-EPS 的实际结果是 **不符合**，两条超标：

| 需求 | 限值 | 实测 | |
|---|---|---|---|
| `electrical_power` | ≤ 600 W | 1432 W | 超标 |
| `parking_hand_torque` | ≤ 5 N·m | 10.3 N·m | 超标 |
| `motor_peak_torque` | ≤ 8 N·m（目标 6.4） | 7.29 N·m | 边际 |

三条说的是同一件事：**原地全锁高附时助力饱和了**。手上多出来的 5 N·m、
电机吃掉的 7.29/8.0、超预算一倍多的峰值功率，都是这一个原因的三个侧面。
12 V 系统给 1.4 kW 机械轴功率意味着 120 A 以上 —— 重型车 EPS 往 48 V 走，
通常就是被这一条推过去的。

### `steering_feel` —— 今天判不了

ISO 13674 口径的中心区与回正要求。**故意收进来的**：客观试验与指标库（v2 V3）
落地之前，对它做检查会报"覆盖不全"，并逐条点名缺哪个测量。

需求先于试验能力存在，这是开发的常态；两者之间的差就是工作清单。让它显形，
比藏起来有用。

## 8. 这些数字算什么

- **作动器限值**来自所选电机的铭牌与一条明写的设计余量（铭牌 80%）—— 精确。
- **电气预算**是整车约束，不是实测；而且指标是电机**机械轴功率**，
  实际电流还要除以驱动效率，所以那条限值是电气需求的**下界**。
- **手力矩与手感带**是同级别产品的普遍预期，属于工程判断。

每一条都在自己的 `source` 里说清楚是哪一种。整个工具的适用边界照旧：
经解析闭式解与内部一致性验证、golden 逐位可复现，**未经实车或台架相关性验证**。
目标层不改变这一点 —— 它只是让"对着什么判"这件事本身可被审阅。
