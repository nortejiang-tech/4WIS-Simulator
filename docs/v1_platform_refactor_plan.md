## 0. 一句话诊断

CarSim/CarMaker 的"好用"不是皮肤，而是一套工作流范式：**一切皆数据集、试验是一等公民、求解器与界面解耦、每次运行留下可分析的结果资产**。本项目物理底座（model_core 统一数学层、三档模型、负载分析）已经达标甚至更透明，差的是这套范式——现在的产品本质是一个"实时驾驶仪表台"，而不是"仿真实验平台"。

## 1. 差距分析：对标 CarSim / CarMaker

| 能力 | CarMaker 范式 | 本项目现状 | 差距定级 |
|---|---|---|---|
| 试验定义 | TestRun = 车辆+场景+机动+驾驶员+环境，文件化、可复现、可版本管理 | project YAML 只存 车辆+策略+场景；机动（开环激励）在**前端 wall-clock 定时器**里生成，不可复现、不可批量 | ★★★ 核心 |
| 求解器形态 | 独立求解进程，GUI 是客户端；离线可加速 | `Simulator` 全局单例 + asyncio 实时步进，**只能 1× 实时**；物理本身可跑 >100× 实时 | ★★★ 核心 |
| 批量/扫描 | Test Series：参数矩阵 × 机动 → KPI 表 + 通过/失败判据 | 无。A/B 对比靠前端手动"捕获" | ★★★ 核心 |
| 结果资产 | 每次运行落盘 .erg/.dat，随时回查 | Recorder 是内存环形缓冲，手动导 CSV；关浏览器/重启即失 | ★★★ 核心 |
| 后处理 | IPGControl/VS Visualizer：通道树、多 run 叠图、游标、FFT | ChartPanel 实时曲线（30 s 环形缓冲）；无 run 浏览器、无叠图工作台 | ★★★ 核心 |
| 回放动画 | 动画与曲线共享时间游标，可拖动 | 无回放，只有实时视图 | ★★ 重要 |
| 参数界面 | 每个参数屏带几何示意图 | ParamsPanel 纯表单；理论页已有现成 SVG 资产未复用 | ★★ 重要 |
| KPI 体系 | 标准试验（ISO 4138/7401/3888）+ 判据 | ScorePanel 7 项指标，算在**前端 30 s 缓冲**上，不随 run 存档 | ★★ 重要 |
| 驾驶员模型 | IPGDriver：预瞄+速度规划+倒车 | pure pursuit + 曲率限速（雏形已不错），无速度剖面、无倒车 | ★ 增强 |
| 信息架构 | 按工作流：建模→场景→试验→运行→分析 | 5 个侧栏 tab 堆 17 个面板，按"功能"而非"工作流"组织 | ★★ 重要 |

**结论：四个 ★★★ 全部指向同一个根因——缺"实验(Experiment)→运行(Run)→结果(Artifact)"这条主干。** UI 重构如果先做，只是给仪表台换壳；主干立起来后，UI 自然按工作流重排。

## 2. 重构方案

### 架构原则

1. **求解内核与实时循环解耦**：把"建模型+建策略+场景+逐步积分+记录"抽成无 I/O 的 `SimSession`；现有实时 `Simulator` 和新的批量 `BatchRunner` 都是它的宿主。
2. **实验是文件**：`experiments/*.yaml` 描述完整试验；**机动（maneuver）按仿真时间驱动**（现 ScriptRunner 是 wall-clock——改造为 sim-time，实时/离线两用）。
3. **每次运行留资产**：`runs/<id>/meta.json + data.csv`（含全通道 + KPI + 参数快照）。先 CSV（零新依赖），数据量上来再升 parquet。
4. **前端只做客户端**：开环激励、评分全部下沉到后端（当前前端实现降级为"编辑器 + 预设"）。

### Phase A（v0.10）— 实验底座（后端为主，约 2–3 个工作日程）

- A1 `Experiment` schema：vehicle_profile/params + model_type + strategy(+mode_params) + scene + path + maneuver(段序列，扩展现有 action_schema：每段带 终止条件 时长/距离/速度) + dt/时长 + KPI 选择 + 元数据。
- A2 `SimSession`（内核抽取）+ `ManeuverRunner`（sim-time 版 ScriptRunner，实时循环同样复用 → 开环激励从此可复现）。
- A3 `BatchRunner`：离线全速跑 N 个 run（顺序或进程池），落盘 artifact；KPI 后端计算（迁移 ScorePanel 数学并扩展：横摆增益、响应时间、超调、稳定时间、扫频带宽、DLC 通过性）。
- A4 扫描矩阵：参数路径 × 值列表 × 机动 → run 集 + KPI 汇总表。
- A5 REST：`/api/experiments` CRUD、`/api/batch` 启动/进度(WS)、`/api/runs` 列表/通道查询/删除。
- 验收：一条命令/一次点击跑完"LS9 × {前轮转向, RWS 车速调度, 理想阿克曼} × ISO 双移线 @ 60/80/100 km/h"= 9 个 run，出 KPI 对比表，全程 < 1 分钟。

### Phase B（v0.11）— 界面壳重构（前端为主，约 3–4 个工作日程）

- B1 信息架构改为工作流六段（左侧导航 rail）：
  **① 车辆**（profile 数据集管理 + 参数分组表单 + 复用理论页 SVG 做参数示意图）
  **② 场景**（scenario / path / 扰动统一编辑器，即现 2D 编辑能力的归位）
  **③ 试验**（maneuver 段编辑器 + 实验组装器 + 扫描矩阵定义）
  **④ 运行**（现驾驶工作台 = 交互模式；加批量队列与进度）
  **⑤ 分析**（run 浏览器 + 图表工作台：通道树、拖拽建图、多 run 叠图、游标读数、KPI 表、导出）
  **⑥ 原理 / 负载特性**（保留现页）
- B2 布局系统：**推荐 dockview**（MIT、React、IDE 式可拖拽分栏/标签，CarSim 质感的关键）用于"运行/分析"两页；其余页用固定两栏。保守备选：自研折叠栏（少一个依赖，损失 60% 体验）。
- B3 回放：run artifact 驱动 Canvas2D/3D + 时间轴 scrubber（渲染层已按 state 绘制，回放只是换数据源）+ 曲线联动游标。
- B4 全局：命令面板（⌘K，搜参数/动作/页面）、单位体系（per-channel 单位与 deg/rad、km/h 切换）、快捷键说明页。
- 现有 17 个面板全部保留复用，只是重新归位；ExcitationPanel → 试验页机动预设；ScorePanel/ComparePanel → 分析页（数据源改后端 KPI）。

### Phase C（v0.12+）— 面向 4WIS 开发的深度功能（按需逐条批）

- C1 标准试验库：ISO 4138 定圆（出不足转向梯度曲线）、ISO 7401 阶跃/脉冲、ISO 3888-1/2 双移线（锥桶几何+碰撞判定，path 已有 cones 字段）、蛇行、最小转弯直径/原地转向、低速泊车机动。
- C2 4WIS 专属分析页：
  - 执行器功率/能量预算（rack force × rack 速度 → 功率时间历程与峰值，选电机直接可用）；
  - ICR 可达域可视化（转角/速率约束下的瞬心可行区，4WIS 构型设计工具）；
  - 轮胎摩擦利用率地图（四轮 μ 利用随机动的展开）；
  - **失效模式批量矩阵**：fault × maneuver × 速度 → 安全 KPI 表（横摆峰值、路径偏差、可控性判级），支撑 ISO 26262 论证——fault 注入框架已有，缺的正是批量底座。
- C3 物理深化（沿用 v0.9.0 遗留清单）：时域 c_α(Fz) 开关、防倾杆刚度分配横向载荷转移、制动/handbrake 模型、执行器功率/力矩饱和闭环（现在 torque_steer 只是诊断，不约束转向作动器）。
- C4 稳定性边界自动图谱：不足转向梯度、横摆阻尼 vs 车速——直接服务 RWS 调度曲线设计。
- C5 报告导出：单文件 HTML（参数快照+图+KPI），可贴飞书。

### 技术选型与约束

- 后端零新增重依赖（numpy/fastapi/yaml 足够；CSV 起步）；进程池仅标准库。
- 前端新增依赖仅 dockview（若批准）；框架不换（React+zustand+uPlot+Konva+three 全部续用）。
- 单例实时 Simulator 保留（交互驾驶体验不变），批量走独立 SimSession——互不干扰，8010 端口约束不变。
- 兼容性：projects YAML 平滑升级为 Experiment 的子集；旧文件可读。

## 3. 建议决策点

1. **顺序**：推荐 A→B→C。若你更想先看到界面变化，可 B1/B2 先行，但分析页会是空壳。
2. **dockview 引入与否**（B2）。
3. Phase C 各条独立排期，逐条审批。
