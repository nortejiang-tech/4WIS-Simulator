# 计划：表格化 K&C 悬架 · 轮胎瞬态 · 转向执行器闭环

> 目标不是"追平 CarSim"，而是**让这个工具能进底盘工程的工作流**。
>
> CarSim 的悬架模型本质是查表——表来自 K&C 台架实测。整车厂的链路是
> 「台架测 → 灌进模型 → 与实车相关性标定 → 在模型上调」。本工具目前**没有摄取
> 真实悬架数据的入口**，这是结构性差距，比任何单点公式精度都重要。

---

## 现状盘点（读码确认，非印象）

悬架参数**全集**只有：`caster_angle`、`kingpin_inclination`、`camber`、`scrub_radius`、
`spring_rate`、`damper_rate`、`anti_roll_rate`（+ 前后分配）、`kingpin_mu`。

| K&C 项 | 现状 | 影响 |
|---|---|---|
| 外倾随行程（camber gain） | **常数**，不随行程/侧倾变 | 侧倾时外侧轮外倾不变 → 极限侧向力系统性偏高 |
| 前束随行程（bump steer） | 单个线性系数 `bump_steer_coeff` | 真实前束曲线非线性且常有拐点，线性系数表达不了 |
| **柔性转向/外倾（compliance）** | **完全没有** | 真车里柔性贡献与几何相当；缺了就只能靠倒推参数凑操稳平衡 |
| 主销后倾随行程 | 常数 | 回正力矩随行程的变化丢失 |
| 轮距/轴距随行程 | 无 | |
| 侧倾中心 / 侧倾轴 | 无，侧倾力矩直接绕 h_cg | 几何载荷转移与弹性载荷转移分不开 |
| 抗点头/抗抬头 | 无 | 点头/抬头只有质量转移，没有几何贡献 |
| 杠杆比 motion ratio | 无，`spring_rate` 直接当轮心刚度 | 无法与实车弹簧参数对应 |
| 缓冲块 / 拉伸限位 | 无 | 大行程、路肩、极限工况缺失 |
| 减振器非线性 | **线性** | 复原/压缩不对称、退让性缺失 |

轮胎：线性+摩擦圆 或 简化 Pacejka（4 参数纯滑移 + 摩擦椭圆裁剪）。
**无松弛长度、无 μ(Fz) 衰减、无真正的 MF 联合滑移。**

转向：齿条/横拉杆硬点连杆求解 **已有且质量不错**，但 `torque_steer` /
`motor_torque_demand` **只是诊断量，不闭环约束执行器**——健康执行器永远不会被力矩限住。

### 一条实证

上一轮为了把不足转向梯度从 0.07 deg/g（近乎中性）调到量产区间，我先试了**前后侧倾
刚度分配**——结果 K 只从 0.071 动到 0.085。原因：`c_α ∝ Fz^0.8` 下现实载荷转移只让轴
损失不到 1% 能力。最后只能**直接改前后侧偏刚度比**（0.80/1.20）凑出 K=1.49。

**那是倒推参数，不是建模。** 真实机理里柔性转向和 μ(Fz) 衰减各占一块，而两者都缺。
本计划的验收之一就是：T1+T2 落地后，这两个 scale 应能退回 1.0，让不足转向从物理里长出来。

## T1 — 表格化 K&C 悬架接口（单项价值最大）

### 数据模型

按 K&C 台架的实际输出组织，分两族：

**(a) 运动学 —— 悬架行程 z 的函数**（台架 jounce sweep 直接产出）

```
toe(z)          前束曲线（bump steer）
camber(z)       外倾曲线（camber gain）
caster(z)       主销后倾曲线
half_track(z)   轮心横向位移
wheelbase(z)    轮心纵向位移
```

**(b) 柔性 —— 轮上力/力矩的函数**（台架 compliance test 直接产出）

```
Δtoe    = C_toe_Fy·Fy + C_toe_Fx·Fx + C_toe_Mz·Mz
Δcamber = C_cam_Fy·Fy + C_cam_Fz·Fz
Δx      = C_x_Fx·Fx          纵向柔性
Δy      = C_y_Fy·Fy          横向柔性
```

### 表示与单位

- 运动学用 **1-D 网格 + 线性插值**（台架就是一串离散点）
- 柔性默认用**线性系数**，但同样支持给表（大变形下柔性本身非线性）
- **文件里用工程单位**（deg、mm、kN、deg/kN），装载时转 SI。台架报告就是这么写的，
  让人手抄不出错比内部一致更重要

### 文件形式

新增 `kc_profiles/`，与现有 `vehicle_profiles/` 同构（同一套 loader 心智）：

```yaml
profile:
  name: ls9_front
  axle: front
  source: "K&C 台架报告 2026-XX / 或：工程估算"
kinematics:
  jounce_mm:   [-100, -50,  0,   50,  100]
  toe_deg:     [0.12, 0.05, 0.0, -0.06, -0.14]
  camber_deg:  [1.20, 0.58, 0.0, -0.62, -1.30]
  caster_deg:  [...]
  half_track_mm: [...]
compliance:
  toe_per_fy_deg_per_kN:    -0.05
  toe_per_fx_deg_per_kN:     0.02
  toe_per_mz_deg_per_kNm:   -0.30
  camber_per_fy_deg_per_kN: -0.08
```

另配 CSV 导入器，直接吃台架导出。

### 接入点

现有的 `static_toe_offsets()` / `camber_per_wheel()` 返回常数——这是天然的缝：

```
δ_eff = δ_cmd + toe_static + toe_kin(z) + toe_compliance(F)
γ_eff = γ_static + camber_kin(z) + camber_compliance(F)
```

- **multibody**：已有每角 `comp`（悬架压缩量）→ 直接喂运动学表；已有轮胎力 → 喂柔性。干净。
- **simplified_dynamic**：**没有悬架行程状态**。用准静态载荷反推 `z = (Fz − Fz_static)/k_s`
  ——该模型本来就在算 Fz，成本为零，且与它自身的准静态假设自洽。

### 一个必须处理的因果环

柔性依赖轮胎力 → 轮胎力依赖侧偏角 → 侧偏角依赖前束 → 前束依赖柔性。**代数环。**

取**一步滞后**（用上一步的力），与项目里开放差速器的做法一致，并写明理由：200 Hz 下
力的变化时间尺度是 ~100 ms 量级，一步 5 ms 的滞后可忽略。不做步内迭代——增加复杂度
和不确定的收敛性，换不到可辨识的精度。

### 向后兼容

无表 → 行为与现在**逐位一致**（硬指标，按前几轮的做法全精度逐 KPI 验证）。
`bump_steer_coeff` 降级为「合成一张线性 toe(z) 表」的快捷方式。

### 验收

- 无表时 golden 逐位不变
- 给一张已知的前束曲线，实测 bump steer 与表吻合
- 给柔性系数，稳态圆周下测出的**柔性转向量**与 `C_toe_Fy·Fy` 吻合
- 不足转向梯度 K 能通过**柔性**而非侧偏刚度倒推被调出来

## T2 — 轮胎瞬态与载荷特性

三件事，按对结论有效性的影响排序：

### T2.1 松弛长度（最优先）

轮胎侧向力不是瞬时建立的：`dα'/dt = (v/σ)·(α − α')`，σ 典型 0.3–0.8 m，
60 km/h 下约 30 ms。

**为什么这条对本项目是硬伤**：`rear_wheel_steer` 有 `transient`（稳态+瞬态）和
`model_following` 两个模式，它们的全部价值在于**前后轴力建立的相位关系**。现在后轮
一给角、后轴力立刻到位——**瞬态反相策略的收益被系统性高估**，基于它调出来的参数
和得出的结论都要打问号。

实现：每轮增加滞后滑移状态 α'、κ'，与轮转动一起积分。σ=0 → 关闭 → 逐位不变。

### T2.2 μ(Fz) 衰减

`μ(Fz) = μ0·(1 − k_μ·(Fz/Fz_nom − 1))`，k_μ ≈ 0.1。这是**载荷转移导致轴能力损失的
主要机制**，比 c_α 的凹性强得多——也是上面"侧倾刚度分配调不动 K"的一半根因。
k_μ=0 → 关闭。

### T2.3 真正的 MF 联合滑移

摩擦椭圆裁剪 → MF 联合滑移加权函数。形状和不对称性都不同。
（TIR 文件导入后置——先把机理补上，数据接口是另一件事。）

## T3 — 转向执行器闭环

把**已有的**齿条力链接回去：主销力矩 → 齿条力 → 电机扭矩需求 → 与扭矩上限比较 →
超限时约束可达角速度/角度。增量不大（资产都在），但对 4WIS 是安全相关的：整个单轮
失效研究建立在"执行器失效会怎样"，而"执行器接近能力边界"这个中间状态目前不存在。

---

## 排序与理由

```
T1 (K&C 表格)  ──┬─→ T4 (K&C × 四轮解耦研究)
                 │
T2.1 (松弛长度) ─┴─→ 重估 RWS 瞬态策略结论
T2.2 (μ(Fz))   ──→ 退掉侧偏刚度倒推
T3 (执行器闭环) ──→ 故障研究扩展
```

**T1 先做**，因为它同时解锁了 4WIS 领域真正没人做过的方向：柔性转向在传统车上是调校
细节，在**后轮转向车上是串在执行器后面的未建模环节**；在四轮解耦车上更是直接推翻
"我能把每个轮子放到我要的角度"这个前提——你命令的角度和实际得到的角度不一样，
而且随载荷、随驱动力、**随每个角独立地**不一样。

**T2.1 与 T1 并列优先**，因为它决定现有 RWS 瞬态结论是否成立。

---

## 基线影响预期

T1/T2 的默认值都设计成"关闭 = 逐位不变"，所以**机制落地本身不动基线**。
真正动基线的是随后给默认车填 K&C 表和 σ——那一步单独做、单独记台账、单独重算安全研究。

---

## 不做的

- **Adams 式连杆求解器**。CarSim 自己都不这么做——表格既快又直接来自测量。
  投入产出比远不如 T1。
- ADAS 传感器 / 交通流 / 道路库。
- 动力总成深化（变速箱、发动机 map）——纯电场景，现有扭矩-功率包络够用。
